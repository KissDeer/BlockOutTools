# 网页工具使用

## V2 重做版（当前优先）

### 启动与打开

V2 使用 Node.js 20+。依赖已安装时可双击根目录`Start-BlockOutTools-V2.cmd`：它会在可见命令窗口启动 Vite，并在服务就绪后由 Vite 打开浏览器。它不隐藏进程、不绕过执行策略、不自动下载依赖。首次运行或锁文件变化后安装依赖：

```powershell
cd D:\GameDesgin\BlockOutTools\app-v2
npm install
npm run dev
```

打开 `http://127.0.0.1:4174/`。Vite 固定使用 `4174`，端口被占用时会直接报错，先核对占用进程，不要启动多个 V2 服务。根目录 `Start-LayoutTools.cmd`仍启动旧兼容宿主，不是 V2 入口。

### 当前工作流

1. 首屏直接进入无限画布。模块节点会按内部积木的真实 XY、尺寸和旋转显示自适应俯视缩略图；出入口箭头位于内部摆放的相对位置并保持同一朝向，可直接拖动连接。左侧选择、新建或复用模块；拖动节点只改变关系图位置，不改变实际组装 Transform。
2. 双击节点或在右侧点击`编辑内部`。左侧统一目录当前提供 Box、Doorway、Stairs Linear 和模块出入口。
3. 选中积木后用画布直接拖动，或在右侧编辑位置、Z、旋转和关键几何参数。出入口使用同一选择、变换、复制和删除机制，并以箭头显示局部正方向。
4. 点击`返回组装`，从一个模块端口拖到另一个未占用端口，或依次点击两个端口，建立当前选择的连接类型。端口命中点使用内部积木的真实相对位置；同一模块的复用实例分别计算端口占用。选中连线后可在右侧修改八种连接类型或删除，`Delete` / `Backspace`也会删除选中连线。连接会在 3D 与 UE dry-run 阶段求解模块相对 Transform，但不会自动生成门、楼梯、电梯或道路连接器实体；三维楼梯只来自模块内部已有的 Stairs Linear 积木。
5. `3D 预览`默认收起。展开后覆盖左侧模块库以外的工作区；只有点击`刷新`或顶部刷新按钮才重建。每个连通分支以第一条连接的源实例为锚，其余实例按端口位置、相向方向和连接类型偏移拼装；标题显示端口拼装是否闭合。Box、Doorway 和 Stairs 使用与 UE 计划同源的部署解释，Port 不进入三维。
6. `UE 计划`显示本地 dry-run Actor、坐标和稳定同步键。当前不连接 Unreal、不执行 Apply。

### 四类 Phase 0 积木

| 积木 | 日常关键参数 | 部署行为 |
| --- | --- | --- |
| Box | Transform、`BoxSize[X,Y,Z]`、主体色、顶面色 | 一个 Blueprint Actor；用于楼板和墙 |
| Doorway | Transform、洞口尺寸、顶部厚度、侧边厚度、两种颜色 | 一个 Blueprint Actor；3D 展开为左右侧和顶部 |
| Stairs Linear | Transform、`StairsSize[X,Y,Z]`、台阶数、两种颜色 | 一个 Blueprint Actor；3D 按台阶数逐级展开 |
| Port | Transform、箭头长度、通行宽度 | 只用于模块关系，不进入 3D 或 UE |

### 桌面快捷键

- `W` / `E` / `R`：移动、旋转、缩放模式。
- `Ctrl+C` / `Ctrl+V`：复制和粘贴当前模块实例或内部积木。
- `Ctrl+D`：直接复制当前模块实例或内部积木并偏移。
- `Delete` / `Backspace`：删除当前选择；删除实例时同步清理它的连接，保留模块定义。
- `Ctrl+Z` / `Ctrl+Shift+Z`：撤销和重做。

输入框获得焦点时不会触发画布快捷键。V2 只维护桌面键鼠流程，最低目标视口为 `1280x720`。

### 保存与文件

当前每次命令后约 350ms 自动保存到浏览器本地草稿，刷新和服务重启后恢复。顶栏可导出 `*.blockout.json`并重新打开，打开时通过版本化 Zod Schema 校验。项目清单、模块分文件、原子磁盘保存和三方合并属于后续阶段，不能把当前浏览器草稿描述成已经完成的团队文件工作流。

## 旧版兼容宿主（仅迁移与历史参考）

### 启动与打开

仓库需要 Node.js 20 或更高版本。Windows 下首选双击根目录的 `Start-LayoutTools.cmd`：它会在最小化但可见的 `LayoutTools Server` 命令窗口中启动服务、等待页面可用并打开浏览器；服务已运行时只打开页面，端口被其他程序占用时会显示错误。关闭该服务窗口即可停止服务。

也可以在 `D:\GameDesgin\BlockOutTools` 中运行：

```powershell
npm install
npm start
```

`npm install`只需在首次运行或锁文件更新后执行。

打开 `http://127.0.0.1:4173/`。默认端口被占用时，先核对监听进程；需要改端口可设置 `LAYOUT_TOOLS_PORT`。不要同时启动多个本项目服务。

### 推荐工作顺序

1. 启动后默认进入无限画布组装工作台；需要切换文件时，打开右下角 `本地` 面板确认当前文件或从列表选择 JSON。
2. 在工作台新建、复用或选择楼层模块；双击模块进入其内部画布。
3. 在内部画布设置关卡名、网格、旋转步长、图层和各层高度，并用原有积木或右下角 `UE` 面板中的参数化积木搭建布局。
4. 返回组装工作台，用平面、层高展开和手动刷新后的三维预览检查模块拼接、墙体和楼梯连接。
5. 等待自动保存状态完成；阶段版本用不同文件名执行 `保存当前`。
6. 需要跨工具迁移时再使用 JSON、FBX、GLTF、OBJ 或 UE 桥接。

### 本地关卡库

- 默认目录：`D:\GameDesgin\BlockOutTools\data\levels\`
- 默认文件：`autosave.json`
- 编辑后约 800 ms 自动保存到当前文件。
- 页面刷新或服务重启后恢复最后打开的有效文件。
- `保存当前` 可另存；文件列表可刷新并选择打开。
- 可在启动前设置 `LAYOUT_TOOLS_DATA_DIR` 指向其他绝对目录。
- `data/levels/`中的 JSON 和 `.library-state.json`随仓库提交，用于共享示例和当前恢复入口。个人关卡应通过`LAYOUT_TOOLS_DATA_DIR`保存到仓库外目录。

切换文件前，页面会先保存当前文件。若打开失败，先检查 JSON 是否包含 `shapes`、`entities`、`layers` 三个数组。

### 原有 LayoutTools 能力

左侧工具包括选择、矩形、基准框、门窗、墙体/楼梯、实体、测量、Polygon、图片、切割、撤销重做和网格。右侧设置和图层面板负责：

- 关卡、网格、旋转和标签设置。
- 图层、分组、可见性、锁定、层高、3D 墙体及目标层。
- 门窗颜色与高度、3C 胶囊体、实体图标。
- 2D、3D 和图层分离视图。
- JSON、PNG、FBX、GLTF、OBJ 与单位换算。

右侧 `导出缩放 / 单位换算` 会写入关卡的 `exportScale`。画布边缘尺寸按目标单位显示，左下角状态标明倍率和单位；网页内部坐标仍以厘米保存。UE 面板的 `使用当前网页` 会直接读取这组最新设置；修改比例或画布后需要重新执行 `检查导入`。

需要具体手势、快捷键、布尔运算、路网、测量或导出字段时，查阅仓库根目录的 `USER_MANUAL.md`。它是原始功能说明，不随本地扩展改写。

### 楼层模块组装

启动后默认显示无限组装画布；关闭后可通过右下角 `模块` 再次打开。模块定义拥有或引用一个内部源图层；内部源图层保存真实楼板、墙体、原有积木和 UE 参数化积木，外部实例只保存独立位置、层高和旋转。修改内部内容会更新所有复用实例，而每个实例可以整体移动、旋转和连接。

推荐操作顺序：

1. 点击 `新增模块`，再在无限画布空白位置放置模块。
2. 双击实例或在左侧点击 `编辑内部`。原 LayoutTools 编辑器会临时只显示该模块的内部图层；可使用全部原有工具和右侧 `放置积木` 列表搭建这一层。
3. 在同一个 `放置积木` 列表选择 `模块出入口`，再像其他积木一样在内部画布连续放置。出入口显示为橙色箭头，箭头尖端是它的正方向；位置、平面尺寸、旋转、复制和删除复用原画布操作，旋转积木会直接改变箭头朝向。选中后在原积木检查器编辑名称与局部 Z。每个出入口形状属于模块定义，所有复用实例共享同一套预设数量。
4. 点击 `返回组装`公布内部几何和出入口。已有单图层设计可用次要入口 `从当前图层导入`，原图层不会转为模块私有数据。
5. 点击 `复用实例`创建另一层。选择连接形式并点击 `连接出入口`：先点第一个出入口，在空白处点击可依次增加路线折点，最后点第二个出入口完成。普通楼梯显示双向箭头；单向类型、螺旋楼梯、电梯和道路使用各自箭头与线型。
6. 无限画布是关系图排版，不是最终世界坐标。可独立拖动模块；选中画布模块后可用顶部 `删除选中`或键盘 `Delete` 删除该实例及其连接，模块定义和内部内容会保留以便再次复用。`Ctrl+C`复制选中实例，`Ctrl+V`粘贴为共享同一模块定义的新实例，`Ctrl+D`直接复制；新实例不会继承连接，并按 200cm 偏移避免重叠。输入框聚焦、连接/放置状态或三维预览打开时不响应这些画布快捷键。实例检查器中的 `删除模块定义`会删除该定义的全部实例与连接；自有内部图层随之删除，导入的原图层保留。双击路线增加折点，拖动折点改道，双击折点删除。一个模块通过多个预设出入口连接多条路线即可形成分支、闭环或同一对模块间的并行路线，每个出入口仍只接一条路线。
7. 用 `平面`检查关系图，用 `层高展开`检查连接的高度语义。无限画布默认隐藏原编辑器左侧工具栏，并把三维预览收起，让关系图使用完整工作区；点击工具栏的 `3D 预览`后，预览会覆盖左侧模块列表以外的整个主工作区，也可从预览右上角收起。点击 `刷新预览`后，工具才按连接图求解最终拼接：每个连通分支以首个模块为锚，相连出入口旋转为面对面，再应用连接类型的水平和 Z 偏移。看到 `待刷新`表示关系或内部内容已变化。Stairs Linear 会按 `StairsSize`、`NumberOfSteps`和旋转逐级显示；带 `layoutRole: "floor"` 的楼板把图层高度视为行走表面，厚度向下延伸。

#### 模块文件与 Git

选中模块定义后可用 `导出模块`生成独立的 `*.layout-module.json`。模块包包含模块定义、内部图层、积木、实体和共同基线，适合放进 Git；`导入模块`会按稳定 ID 合并。当前版本与导入版本修改不同字段时自动合并，修改同一字段时列出冲突并要求整体选择保留当前或采用导入。模块包不包含外部实例和连接；这些仍属于关卡组装图。

Git 可以比较和回退已提交的模块包，也会管理仓库内`data/levels/`的共享关卡与恢复状态。正式复用模块仍应导出到团队约定的版本控制目录，再由网页导入更新；个人草稿使用仓库外的`LAYOUT_TOOLS_DATA_DIR`。

#### 模块内部编辑工作条

进入模块内部后显示紧凑编辑工作条。原画布的点击、Shift 多选、框选、复制粘贴和拖动仍然有效；新增入口统一为：

- `W`移动、`E`旋转、`R`缩放，快捷键可在工作条中改成其他单键。
- 数值区按选区中心编辑 X/Y；旋转输入增量角度；单选矩形可直接编辑宽高，Box、Stairs Linear 和 Ramp 会同步对应平面参数。
- `网格`控制数值变换吸附；画布拖动时原有 `V`顶点吸附仍可用，工作条的`顶点 V`和`贴边`可执行一次最近目标吸附。
- `成组/解组`让组内对象联动选择；`锁定/解锁`阻止误选；`隔离/退出隔离`和搜索只影响当前编辑视图。
- 对齐 X/Y 与分布 X/Y 复用当前多选结果。世界轴和局部轴不分模式。

### 白盒规范

右下角 `规范`打开独立面板，配置当前关卡使用的角色和通行基准：胶囊体、视点、最大跨步、跳跃、门洞、通行宽度、净空、楼梯踏步/踢面、落脚区和坡道角度。规范保存在关卡根级 `blockoutProfile`。

`启用规范检查`控制网页检查；`阻止不合格 UE 导入`控制错误是否禁用 UE Apply。当前自动识别 Doorway、Stairs Linear、Stairs Linear Manual、Ramp，以及显式标记为 `layoutRole:"corridor"`或`layoutRole:"landing"`的形状。检查项可点击定位对应积木。普通楼板不会被猜测为走廊，避免大面积误报。

出入口本身不分进出。单向连接使用第一次点击的端口指向第二次点击的端口；普通楼梯使用双向箭头，垂直升降仍按第一次点击到第二次点击计算高度。一个实例上的一个出入口只能连接一次，分支需要使用模块中预先布置的多个出入口。路线 `waypoints` 只保存无限画布折线，不直接作为三维坐标；最终拼接使用以下规则：

| 连接形式 | 第二个端口相对第一个端口 |
| --- | --- |
| 普通门、单向门 | 同一水平位置和高度 |
| 楼梯 | 沿第一个端口朝向前进 400cm，上升 300cm |
| 螺旋楼梯 | 水平投影重合，上升 300cm |
| 普通电梯、单向电梯 | 水平投影重合，上升 300cm |
| 普通路 | 沿第一个端口朝向前进 500cm，高度不变 |
| 单向下落路 | 沿第一个端口朝向前进 250cm，下降 300cm |

三维解析时目标实例会旋转到两个端口相向。以上未由用户完整定义的距离是当前保守默认值，后续按具体连接块逐项修订。

闭环和并行路线必须使用不同端口。三维解析从每个连通分支的首个实例开始，第一次到达一个实例的路线决定其 Transform；后来闭合到该实例的路线保留为逻辑关系，不重复移动已经定位的模块。因此作者应让闭合路线的两端在预期拼接位置上满足同一连接规则，生成脚本应校验闭合误差。

模块数据位于关卡根级 `structureGraph`，随当前 JSON 自动保存、另存和刷新恢复。出入口在内部图层中仍保存为带 `modulePort:{id,name,z}` 的普通矩形形状，但画布会把它渲染为指向局部 `+X` 的箭头；形状中心和旋转会同步成端口的局部 XY 与朝向，无限画布公布的端口也显示同一正方向。旧文件中的图结构端口会在首次进入内部时自动生成对应形状。删除出入口形状会删除其公布端口和已有连接。删除实例会同时删除它参与的连接；删除无限画布直接创建的模块定义会删除其私有源图层和内部内容，删除从已有图层导入的模块则保留原图层。

### AI 助手

在右侧 `AI` 面板配置服务商、Base URL（如需要）、API Key 和模型。API Key 由原 LayoutTools 的浏览器本地配置管理，本地桥接不读取它。

网页 AI 可使用原有 LayoutTools 积木和 15 类 UE 参数化积木。提示词应写清：

- 空间和层数。
- 平台高度与连接关系。
- 房间、墙体、楼梯和实体要求。
- 是替换现有布局还是增量修改。
- 对 UE 积木有要求时给出积木类型和关键尺寸。
- 需要模块组装时给出每个模块的内部内容、预设出入口数量和连接形式；未说明的出入口不得由 AI 自行增加。

#### AI 如何使用积木

这不是模型直接点击网页或调用 UE Blueprint 的 Tool Calling。UE 面板读到参数化 Schema 后，会在原网页发送模型请求前，把原有积木、15 个 `blockType`、Blueprint 类路径、参数键、范围和枚举值追加到该请求的 system/instructions；模型据此返回标准 LayoutTools JSON。支持原网页使用的 Chat Completions、Responses、Anthropic Messages 和 Gemini GenerateContent 请求格式。

模型返回的参数化积木必须带有 `ueBlockout: { kind: "parametric", blockType, blueprintClassPath, parameters }`；网页根据 Schema 补全和校验参数，再由参数反算二维外形。`config/ue-parametric-blocks.json` 是唯一目录来源，不能在提示词或代码中另维护一份类型清单，也不向模型提供插件内部 StaticMesh `assetId`。

模块组装使用关卡根级 `structureGraph`：新模块以 `ownsSourceLayer:true`拥有内部源图层，已有图层导入模块为 `false`；内部楼板、墙体和端口积木继续写入源图层的 `shapes/entities`，端口形状使用 `modulePort:{id,name,z}`，其中心与旋转同步到模块公布端口；实例保存 Transform；连接引用两个实例端口和上述八种固定类型。AI 请求会同时收到这套 Schema、方向规则和默认距离，并被要求保留现有端口及数量。AI 仍然返回 JSON，不直接点击模块工作台或刷新三维预览。

此过程不会自动写入 UE。模型结果先只更新网页关卡；需要进入 MYMY 时，仍须由用户执行 `检查导入`，核对计划后再明确点击 `导入 UE`。未知 `blockType` 会撤销其 UE 标记并保留普通形状，同时给出警告。

应用 AI 结果后必须检查形状数量、图层高度、地面连续性、楼梯目标层和参数检查器。外部模型可用性不是本地工具的离线能力。

### 图片关系图转模块关卡

先按独立平面或楼层拆模块，再解释颜色与标记，不要直接把图片上的路线描成墙：

- 建筑实体边界转为短 `Box` 墙和连续楼板。
- 路线、箭头和文字标注转为模块命名、内部通行方向和无限画布折线，不生成实体墙。
- 位于同一平面图内部的门或楼梯使用真实 `Doorway`、`Stairs Linear` 等积木。
- 跨平面连接节点转为成对的模块出入口；字母或编号配对转为 `structureGraph` 连接，并按门、楼梯等语义选择连接形式。
- 一个平面图可以有多个预设端口。同一对模块可通过不同端口并行连接，整张关系图也可以闭环，但生成后要校验端口占用、连接数量和三维闭合误差。

V2 的洛斯里克高墙参考图可用确定性脚本生成：

```powershell
npm run generate:lothric-v2
```

随后在 V2 顶栏点击`打开 V2 项目`并选择`layouts/lothric-high-wall-v2.blockout.json`。当前样例含 10 个可编辑模块、A-H 与 J-N 共 13 组连接、连续楼板/短墙段、真实 Doorway 和符合白盒步高/踏步规范的内部 Stairs Linear；圆塔用允许少量重叠的短矩形楼板带和墙段近似。导入后会进入浏览器草稿并在刷新或服务重启后恢复，不会写入 UE。

洛斯里克高墙关系图是可执行样例：

```powershell
npm run generate:lothric-logic
```

脚本 `scripts/generate-lothric-logic-map.mjs` 生成可版本控制的 `layouts/lothric-high-wall-logic-map.json`，同时写入本地关卡库 `data/levels/洛斯里克高墙_全图逻辑关系.json`。当前样例包含 10 个可编辑模块、A-H 与 J-N 共 13 组连接、模块内真实门和楼梯；不会写入 UE。

### 已知基线行为

- 原版 `v0.0.2` 在撤销一次绘制后可能无法重做；当前宿主保留该参考行为。
- 约 768 px 宽视口下，顶部缩放文字可能被挤成多行。
- 3D 视图可能输出 `THREE.Clock` 弃用警告；它不代表画布渲染失败。
- AI 结果质量和图片理解能力取决于用户所选外部模型。
