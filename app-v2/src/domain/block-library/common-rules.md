# 积木通用规则

先读 [索引](README.md)，再读目标文件夹的 definition.json 和 usage.md，最后读取当前项目 blockoutProfile。需要摆放示例时才读 examples。

## 三层规则

- 硬限制：实际文件由 ../project-schema.ts 校验；参数必须有限，尺寸必须为正，身份及引用有效。JSON 中的文字约束用于解释，不是动态执行程序。
- 项目规范：角色尺寸、门净宽、台阶最大高度和最小踏步深度来自项目 blockoutProfile，不把某个项目的标准写成积木硬限制。
- 摆放建议：短段墙壁、少量重叠等属于建议，不作为文件合法性条件。

## 单位、变换与身份

尺寸和位置用 cm，平面旋转用度。位置为模块内部局部位置；画布卡片排版不代表世界位置。网页 Y 到 UE -Y，平面角到 UE 负 Yaw，由转换器负责，生成网页数据时不要提前翻转。

移动只改位置，旋转只改角度，尺寸修改写回类型关键参数。当前不提供自由 Pitch/Roll 或额外 Actor Scale。

修改已有积木保留 blockId。类型 ID 不随中文改名改变；新建或复制对象产生新身份。UE 同步键仍是 projectId/instanceId/blockId。

只写类型允许的参数；Box 的碰撞、渲染及其他材质字段不开放。出入口和连接关系不自动生成门、楼梯或电梯实体。

## 引用与维护

definition.json 的名称、默认参数、部署标志和蓝图路径被 ../catalog.ts 直接读取；默认参数经项目积木 Schema 校验。参数说明、空间语义与用法供人和 AI 阅读，当前不会自动生成属性面板或校验算法。

改默认值仅影响后续新建，不重写已保存积木。definitionVersion 是规则文件版本，与项目 schemaVersion 分开；改变参数含义时必须显式迁移，不能靠提高版本号改变旧关卡。

新增预设优先复用现有类型。新增几何类型需要定义文件、用法、类型/Schema、目录注册、二维与三维表现、UE 映射及测试。目录存在不等于已实现。

在仓库根目录运行 node scripts/generate-block-library-index.mjs 更新索引；加 --check 可检查是否过期。表格由 JSON 生成，不手动另存 Excel 副本。

UE 实测证据需记录引擎/插件版本、资产路径、参数回读及几何对照。当前类路径来自现有代码，实体积木均未在本轮完成 UE 实测；deployable 表示可进入本地导入计划，不表示已验证或已导入。
