## 一根线的两次缺席

上午修的是 `expandLogicModule` 无调用者（双击进节点看不到更深一层），
晚上修的是 `setConceptPane` 无调用者（上传图与识别候选打不开）。

**同一个毛病，两次。** 都是：零件齐全、逻辑完整、有面板、有 import，就是没有按钮。

值得写下来的是**这两次都不是靠读代码发现的**，是用户用的时候撞出来的。
`NON_GOALS.md` 里那条"不把'能演示'当'已实现'"写的就是这个，
但光写下来不够 —— 两次都写在那儿了，还是又犯。

所以给下次留一条可操作的动作：**删或加面板之后，grep 一下它的入口有没有调用者**。
这比"记得要检查"具体。

真正能兜住的是自动测试，但当前测试环境是 node、没有 jsdom，渲染 App 又会牵进
React Flow 与 Konva。补这一层环境是独立的一步，记在 `NOW.md` 里了，没顺手做 ——
和已有的浏览器实测相比，它这轮的边际价值不够高。

## 顺手补的两处

- **识别页自己能收图**。候选要落在图上，图就是识别的前置条件。原来的空状态写着
  "先在「输入上下文」里导入范围图"，等于让人先去别处猜一次。现在识别页自带上传按钮，
  并且明确说出"图是它的前置"。**能在一个地方做完的事，不要拆到两个地方。**
- **文案里还活着的"拆解"全改成"识别"**。拆解那一页早删了，但完整性核对、输入包表头、
  警告文案还在说"不能拆解"，读起来像在指一个不存在的地方。

## 实测的一条完整链路

在浏览器里从上传走到采用：

```
上传 krat-station-draft.png（1265×805）
  → 同步（落盘为合法 PNG，agent 能直接打开）
  → 推候选（3 区域 / 2 链路 / 4 条警告）
  → 拉取 → 图上 3 个标记、警告逐条显示
  → 排除一条 → 标记变淡
  → 采用 → 回到拓扑画布：节点带角色与标高、链路带类型、识别结果已登记
```

**指纹守卫也试了**：`sample-candidate.json` 基于的是另一份输入，套用按钮被禁用并说明原因。
这是对的行为 —— 输入变了就拒绝沿用旧结论。顺带发现 `layouts/krat-station-draft.png`
就是那份样例依据的图，用它才复现得出来，这条也记进 `NOW.md` 了。
