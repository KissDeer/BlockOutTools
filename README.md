# BlockOutTools V2

面向 UE 白盒制作的本地桌面网页工具。**一张画布，按层级往下走**：在逻辑层摆区域、连路线，双击进入某个区域拼它内部的几何，两边随时切换。层级树与面包屑说明"我在哪"。

## 主流程四步

```
① 画布上摆区域、连路线    ② 进入区域拼几何    ③ 3D 预览    ④ 导出到 UE
```

对应界面：`逻辑拓扑` → 双击节点 → `3D 预览` → `UE 计划`。

> 原第 1 步"上传手绘拓扑图，识别出区域"**整条删了**，不是推迟。理由：这一步要求工具猜图上的方位与比例，
> 猜出来的每一条人还得核对一遍 —— 比直接画更慢。见 [删掉识图这一步](design-log/2026-09-17-删掉识图这一步.md)。

## 启动

需要 Node.js 20+。首次在 `app-v2` 运行 `npm install`，以后双击根目录 `Start-BlockOutTools-V2.cmd`。
地址 http://127.0.0.1:4174/ ，保持服务窗口打开。

## 一张画布，两套坐标

| 坐标 | 用途 | 别拿它干什么 |
|---|---|---|
| `graphPosition` | 画布上的排版位置 | 它**无语义**，不影响几何，不参与导出 |
| 节点局部厘米 | 节点内部拼几何用的单位 | 只在那个节点内部成立 |
| 世界坐标 | 整体组装时才产生 | 只在 3D 预览与导出里出现 |

所以"把节点拖到画布左上角"和"这个区域在关卡里的实际位置"是两件事：真实落位在右侧检查器的**落位与朝向**里填。

## 区域与链路

1. 在 `逻辑拓扑` 建区域、连链路，标出单向门、锁钥门与起点。每个区域四边都有连接点，可以拖出或接入连线。
2. 节点的**落位与朝向**是可选的：没填的节点在展平时会落在原点并被计入"未落位"，导出时按原点处理，**必须在 UE 里手工摆**。界面会把它们列出来，不会假装摆好了。
3. 一个区域可以同时装**自己的几何**和**更下一层的子区域**。两层都非空时，双击进去是**分屏**：左边这一层的逻辑图，右边这个区域自己的拼接图，中间分隔条可拖。

## 拼几何

左侧积木栏挑积木，画布上摆。当前有四种：`box`（楼板 / 落脚平台 / 墙壁 / 包边）、`doorway`、`stairs-linear`、`port`。

- **box** 标记行走表面后，厚度向下延伸；切换基准保持实体位置不动。
- **stairs-linear** 按两端落脚点与高度求解。空间不足**直接报错**，不移动平台、不拉长楼梯凑数。
- 多选拖动是**一次撤销**，不是一条一节点。
- 右侧检查器给这个区域的属性、它的内部、以及落位与朝向；分屏时积木属性与外层逻辑各占一格。

## 3D 预览与导出到 UE

两者**吃同一份展平几何**（`src/domain/node-geometry.ts` 是唯一来源），所以预览里看到的就是会导出的东西。

- `3D 预览`：把整份项目展平成体块渲染。切层级后需要点 `刷新 3D 预览`，状态栏会提示 `3D 需要刷新`。
- `UE 计划`：本地 dry-run，不连 MCP、不写 UE。可以**导出 Actor 计划**（`<项目名>.blockout.actors.json`），
  再用 `scripts/ue_unreal_spawn.py` 在 UE 里生成。
- 同步键格式为 `项目id / 节点路径… / 摆放id / blockId`，UE 侧用它认领自己上一次生成的那个 Actor。
- 计划里的 `assemblyIssues` 是**恒空的兼容键**，不是"检查过没问题"。UE 面板不显示它。

命令行等价物：`node scripts/export-ue-actors.mjs <项目.blockout.json>`。

## 参考资料

`参考资料` 那一格放图与文字（连通关系参考图、空间范围参考图、氛围图、规则与规范、补充说明）。

**工具不解析它们**，也不从它们推出任何东西 —— 区域和路线由人照着材料自己摆。
材料一变，登记过的基准立刻可判为过期（指纹机制），不会静默沿用旧结论。

## 项目文件

顶栏 `文件` 集中提供：保存到磁盘、另存为独立项目、导入 V2 JSON、导出项目备份、打开已保存项目、读取磁盘并合并。
`Ctrl+S` 首次保存，之后编辑自动保存（900ms 防抖）。

- 默认目录 `data/projects-v2/project-<项目身份摘要>/`，一个项目一份 `project.blockout.json`，写入用临时文件 + rename 保证原子性。
- 个人目录用环境变量 `BLOCKOUT_V2_DATA_DIR` 指定。
- 浏览器草稿是恢复副本，顶栏一条状态区分仅存草稿 / 正在保存 / 已保存到磁盘 / 保存失败。
- 磁盘有其他修改时点 `读取磁盘并合并` 可以合不同字段；**同字段冲突会拒绝覆盖并列出路径**，先导出草稿再用 Git 解决。

### 旧项目读不进来（有意为之）

模块层删除之前的项目文件（含 `structureGraph` / `shapes` / `modules` / `instances` / `connections`）**任何入口都会被拒绝**，
并给出"这是模块层删除之前的旧项目文件"的说明，不会假装读成一个空项目。

`layouts/` 里 7 个项目与 `data/levels/` 里 3 个用户文件**保留在仓库里**，作为迁移输入（Phase 3 还没做）。
迁移器应当读旧格式、出报告、写新格式，不覆盖原文件。

见 [旧项目读不出来](design-log/2026-09-17-旧项目读不出来.md) 与 [删掉模块层](design-log/2026-09-17-删掉模块层.md)。

## 验证与边界

- `app-v2` 下：`npm test`、`npm run check`、`npm run build`。
- 网页变更另做**真实桌面浏览器**验证：控制台、操作、非空截图。不维护手机端。
- **"代码里有"不算证据，界面上走得到才算。**
- `box`/`stairs-linear`/`doorway`/`port` 的 UE 参数化 Schema 已确认；CLOSED/SLOPED 楼梯缺少插件实测依据，
  预览里标为 BOX 近似，**不得当成已确认的 UE 几何**。"逻辑连通" ≠ "空间已对接" ≠ "玩法已验证"，不要用一个完成标记掩盖。

需求与范围见 [docs/rebuild](docs/rebuild/README.md)，**明确不做什么**见 [NON_GOALS.md](docs/rebuild/NON_GOALS.md)。
旧版 `layout-tools-workflow` 技能已停用，历史文件仅供查阅。
