# BlockOutTools V2

面向 UE 白盒制作的本地桌面网页工具。主工作面只有“逻辑拓扑”和“拼接搭建”：在拓扑里组织区域、连接和模块，直接打开模块搭建内部，再按需放入整体。项目目标持续提醒，模块结构图、氛围图和设计目标随当前模块显示。

## 启动

需要 Node.js 20+。首次在 `app-v2` 运行 `npm install`，以后双击根目录 `Start-BlockOutTools-V2.cmd`。地址为 http://127.0.0.1:4174/ 。保持服务窗口打开。

## 从拓扑开始搭建

1. 在“逻辑拓扑”整理区域、链路、锁钥和起点；画布位置只用于排版。每个区域上下左右均有连接点，可以拖出或接入连线；新连线保存所选方向，旧连线自动选择朝向相邻区域的边。
2. 在同一拓扑画布框选区域，组成模块并命名；拖入、拖出模块框修改归属，拖模块标题整体移动。归属与位置在松手时一次提交，支持撤销；模块框只是排版分组，不表示真实空间范围。
3. 点模块的“搭建模块”直接进入内部。已有几何原样打开；空模块按需建立稳定定义，不创建整体实例，也不要求参考图、整体位置或先完成其他模块。
4. 在常驻项目提醒填写体验目标和关键约束。在模块参考栏补充目的、目标、结构图和氛围图；同一份资料可以关联多个模块。选择积木时，资料栏继续保留，右侧编辑积木属性。
5. 手工放置积木，或用“快速体块起稿”产生带默认尺寸说明的局部模板；也可使用下文的“AI 初始化参考”。草案先在当前画布预览，采用后继续手工编辑。已有内容需明确确认替换，整次采用可一次撤销。
6. 准备好后点“放入整体”，仅放置当前模块；用实例属性调整厘米位置和旋转、显式连接端口，再刷新 3D。返回按钮保留进入来源，另有“查看整体”；查看和返回都不会重新生成已有实例。

模块资料会显示区域、内部通路和对外接口要求。拓扑改动更新要求，不自动重建白盒；移动拓扑排版不影响几何。可标记“形态已确认”，相关要求或几何变化后提示重新核对；这个标记不代表接口已对接或玩法已验证。

拆解、构型已撤下独立主入口，旧数据和领域生成能力保留。原作用域资料与图片识别仍可从拓扑辅助工具打开，不是手工搭建的必经步骤。

当前实现方案 A+B。自动按拓扑匹配几何端口、整体空间画布整合、完整跨层边界和逐项回改冲突处理属于后续 C；当前沿用显式实例放置、端口连接、属性编辑和 3D。共享子作用域出现多条放置路径时须选择路径，不自动连接所有副本。见 [已确认方案](docs/rebuild/WORKFLOW_UX_PROPOSAL.md)。

## AI 初始化参考

在模块内部展开“AI 初始化参考”，填写本次补充意图，点“准备本模块材料”。界面显示“材料已准备，等待 agent”，可复制任务或导出请求交给本地 agent；工具当前不会自动调用模型。

agent 读取请求中的项目要求、当前模块图片、区域、内外链路和已有几何，按局部草案契约返回结果。点“读取返回草案”或导入结果文件，在画布审阅差异与假设后采用；取消不写入。请求之后相关资料或几何已变时，旧草案不能覆盖当前内容。缺原图会提示，包含图片数据也不等于 agent 已经看过。

“快速体块起稿”是确定性角色模板，不调用 AI、不解读图片。两条路径名称和来源分别显示。HTTP 接口、请求身份和返回格式见 [数据与 AI 契约](docs/rebuild/DATA_UE_AI_CONTRACT.md#10-模块局部草案与上下文当前-ab-契约)。

## 保存与 Git

顶栏“文件”集中提供保存到磁盘、另存为独立项目、导入 V2 JSON、导出项目备份、打开已保存项目和读取磁盘并合并。通过“文件 → 保存到磁盘”或 Ctrl+S 首次保存当前项目；随后编辑自动保存。浏览器草稿是恢复副本，顶栏以一条状态区分仅存草稿、正在保存、磁盘已保存和保存失败。

需要建立另一个关卡文件，使用库内“另存为独立项目”；普通改名只更新当前项目名称。

默认目录为 `data/projects-v2/project-<项目身份摘要>/`，其中 `project.blockout.json` 是项目清单，`modules/` 保存模块文件。模块文件按内容命名，未修改模块不会重复写入；清单最后原子替换。旧模块版本保留用于恢复，不要手动清理。正式项目可整体进入 Git。个人目录用环境变量 `BLOCKOUT_V2_DATA_DIR` 指定。

模块内容文件通过 `.gitattributes` 固定为 LF 换行，避免 Windows 的自动换行转换改变内容哈希；请保留这条规则。

本版在 `schemaVersion: 2` 中新增可选的项目资料、模块目标和形态确认字段，不改变旧坐标与身份含义；新版可直接读取旧 V2 文件。旧版程序未识别这些新增字段，重新保存可能丢弃它们，编辑新资料后请使用本版保存。

磁盘有其他页面或 Git 修改时停止自动保存。点击“读取磁盘并合并”可合并不同字段；同字段冲突显示路径并保留数据，先导出草稿再用 Git 解决。当前没有图形化逐字段冲突选择器。

`data/levels/` 仍保留旧版共享数据，继续跟踪；V2 不会把这些旧文件当成当前 V2 草稿。

## 空间制作

- Box 可标记楼板、落脚平台、墙壁和包边。选择“行走表面 Z”后厚度向下延伸；切换基准保持实体位置不动。
- 直梯检查器的“按上下落脚点计算楼梯”根据两端位置与高度求解。空间不足直接报告，不移动平台或拉长楼梯。
- 选择连线编辑向前间距、横向偏移和终点相对高差；单向通行与高低方向分开。自定义距离在切换类型时保留。
- 实例可设为组装基准；连线只影响拼装，不生成门、楼梯、电梯实体。
- “规范检查”配置尺度并定位问题。3D 支持模块隔离、端口方向和高度剖切。约束闭合不代表全路线可走。

## 从图纸生成

进入模块，“图纸底图”导入 PNG/JPG/WebP，填写已知线段的像素和真实长度校准，设置原点、角度、透明度和图例。可直接对照底图编辑。

导出“解释文件 / 模板”，填写稳定特征 ID、楼板轮廓、墙段、楼梯落脚点与端口，重新读取后逐模块接受。详见 [图纸输入契约](docs/rebuild/DIAGRAM_INPUT.md)。SVG/DXF/PDF 当前先转换成底图，未实现自动 OCR 或任意 CAD 解析。

离线候选生成使用 `node scripts/generate-diagram-project.mjs 基础项目.blockout.json 解释.json 新候选.blockout.json`，与页面使用同一领域生成器。不会覆盖输入或已有输出。

旧 `scripts/generate-lothric-v2-project.mjs` 是历史手工推断样例脚本，发现不合理楼梯时现在会拒绝输出，不再拉长凑尺寸。已有 `layouts/lothric-high-wall-v2.blockout.json` 保留用于回归，不代表真实可走性已验收。

## 验证与边界

在 `app-v2` 运行 `npm test`、`npm run check`、`npm run build`、`npm run verify:level`。网页变更另做桌面浏览器验证，不维护手机端。

“UE 计划”仍是本地 dry-run，不连接 MCP、不写 UE。CLOSED/SLOPED 楼梯缺少插件实测依据，预览标记为 BOX 近似；不得当成已确认的 UE 几何。实际 UE 导入和回读另行执行。

需求见 [docs/rebuild](docs/rebuild/README.md)。旧版 `layout-tools-workflow` 技能已停用，[历史文件](skills/layout-tools-workflow/SKILL.disabled.md) 仅供查阅，不再作为操作依据。旧宿主代码已从当前工作目录移除，历史行为通过 Git 查阅。
