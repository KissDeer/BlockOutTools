# 节点同时装几何和子逻辑，进入复合节点分屏

**日期**：2026-09-17（当日第二次修订，晚于"需求文档回正"）
**状态**：已实现（文档层；代码在做）
**相关文件**：`docs/rebuild/PRODUCT_REQUIREMENTS.md` §4.1、`FUNCTIONAL_REQUIREMENTS.md` FR-04 / FR-05、`NON_GOALS.md`、`REBUILD_PLAN.md` 1-B / 1-E

---

## 起因：一个真实症状

用户报告："双击节点进去看不到更深一层的逻辑图。"

查代码，这个症状其实是**两个独立缺口叠在一起**，只修一个都不够：

1. **子逻辑层造不出来。** `store.expandLogicModule` / `collapseLogicModule` **在全仓库没有任何调用者**（和 `setConceptPane` 完全同一类毛病）。零件是齐的，没有按钮能走到。所以"更深一层的逻辑图"在界面上根本没有产生路径。
2. **就算造出来，也只能看见一半。** 09-17 冻结的规矩是"节点内部**要么**是几何、**要么**是子逻辑，二选一"。进复合节点只看得到逻辑图，进叶子节点只看得到几何。

## 决定

**节点同时持有两者：**

```
逻辑节点
  ├─ blocks        自己的几何（节点局部厘米坐标）
  └─ childScopeId  自己的子逻辑拓扑（下一层节点 + 链路）
```

**进入复合节点 = 分屏**：左边这一层的逻辑图，右边这一层的拼接图，分隔条可拖动。叶子节点没有子层，进去就是全宽拼接图。

用户原话："双击进去以后，默认同时显示——屏幕分成两半，一半是逻辑图，一半是拼接图，共同显示，允许调整两个窗口的大小。"

### 为什么这个改动是对的

两条独立的理由，任一条都够：

1. **产品直觉**：节点就是关卡里的**一个区域**。它内部有哪些子区域、怎么连通，是逻辑图；它自己长什么样，是拼接图。这两样讲的是同一个东西的两面。逼迫二选一，等于进一个区域就必须丢掉一半上下文——人得在两个视图之间来回切，而"切过去就不知道自己在哪"正是 09-17 要修的病。
2. **数据上也更省**：原来的模型里，一个区域的位置信息散在两处（拓扑里的 `relativePosition` + 组装里的 `assemblyTransform`），两边都可能被改。改成"节点的 `relativePosition` 既是它在父级的落位、也是它自己这套坐标的原点"之后，**子区域摆在哪里只有一份数据**，几何视图不重复存位置。

### 放弃了什么

- **放弃"二选一"这条不变量。** 09-17 刚冻结的 FR-05 第二条被本次推翻，原文保留在 git 与本文"考虑过的选项"里。
- **放弃"一个子作用域被多个节点共用"。** 原来的 `childScopeId` 挂在 `LogicModule` 上，多个模块可以指向同一个作用域（`concept-scopes.test.ts` 里的"两个鬼屋共用一个内部"）。移到节点上就变成一对一。这与 NON_GOALS 写的"嵌套是一棵树，不是图"一致，所以不是新放弃的东西，只是**让代码追上已经宣布的立场**。已在 NON_GOALS 单列一行，写明重新评估条件。

## 考虑过的选项

### 右边那半显示什么？

| 选项 | 代价 |
|---|---|
| **这个节点自己的几何** ✅（用户确认） | 需要把 `relativePosition` 从"历史残留"升格成"落位"，并给它一个编辑入口 |
| 根层那张整体摆放图 | 它是要删掉的旧模型；而且和左边不是同一层的东西，放一起更容易看晕 |
| 右边再分页签切换两种 | 多一个状态要维护，且与"不用顶层页签"的原则相冲 |

### 位置信息存一份还是两份？

| 选项 | 代价 |
|---|---|
| **只存在拓扑里**（`node.relativePosition`） ✅ | 几何视图不能独立摆放子区域，必须回到左边摆 |
| 几何里也存一份 | 同一个事实两个出口——NON_GOALS 明确点过名："这类重复不会自己消失，只会让人不确定该信哪一个" |

### 先改哪个：分屏，还是模型？

**先改模型。** 分屏是"能不能看见"，模型是"有没有东西可看"。在 `LogicNode` 还只有一个 `moduleId` 指针的时候做分屏，右边那半没有数据可读，只能读旧的模块实例——等于把一个新界面焊在要拆的承重墙上。

所以顺序仍是 `REBUILD_PLAN` 的 1-B → 1-E，只是 1-E 的内容从"导航打磨"扩成"接入口 + 分屏"。

## 已知边界与风险

- **过渡期两套含义并存**：`childScopeId` 在新代码里挂节点，在旧数据和旧代码里挂模块。读取必须收敛到**一个裁决点**（`node-geometry.ts` 的 `scopeOwnerOf` / `nodeOwnedBlocks`），不能各处各写一个 `??`。1-F 删模块层时把回落一起删掉。
- **`relativePosition` 目前是空的**：它现在被界面标注为"仅供旧资料追溯"。在它变成真正的落位、并且有编辑入口之前，展平出来的几何会全部叠在原点——看起来像 bug，实际是入口缺失。
- **仓库里 7 个真实关卡文件全是旧模型**（`layouts/*.blockout.json`，1–14 个模块/实例，`concept` 字段完全没有）。它们没有逻辑拓扑，套不上五步流程。本次不迁移、不改写它们，靠读取期回落让它们仍能打开；1-F 之后它们退化为只读。
- 本次修订**没有降低对"复用同一个子树"的评估**——只是把代码收紧到与已在 NON_GOALS 里的立场一致。
