# 删掉模块层

**日期**：2026-09-17（1-F）
**状态**：已实现
**相关文件**：整个 `src/domain` 与 `src/features`；见下方"删了什么"

---

## 这一步是什么

把"模块"从项目里彻底拿掉。不是改名、不是降级 —— 是**再也没有这个概念**：

```
删之前：节点 ──moduleId──▶ 模块定义 ──▶ 积木
                              ▲
                              │ 实例的 assemblyTransform 决定它摆在哪
删之后：节点 ──▶ 积木（节点局部厘米），落位由节点自己的 relativePosition 决定
```

这一步能做成，是因为前面 1-B 与 1-C 已经**先把承重墙换成新墙**：
几何早就挂在节点上、3D 与 UE 早就读展平节点几何了。所以这次删的是隔墙。
前两次尝试整轮回退，都是因为反过来做。

## 删了什么

**领域**：`assembly-resolver`（组装求解器）、`module-workflow`、`module-preview-project`、
`module-draft` + contract、`diagram-import`、`connection-labels`、`concept-decomposition`、
`LogicModule` 类型与 `scope.modules` 字段、`ModuleDefinition` / `ModuleInstance` / `Connection` 类型、
`logicModuleSchema` 与"节点被分到多个模块"那几条校验、以及 `node-geometry` 里的**实例回落**。

**界面**：整个 `features/assembly/`（装配画布、侧栏、两个检查器、模块节点、连线渲染）、
模块草案面板、底图/解释文件工具、`ModuleContextPanel`、画布上的**分组框**（含折叠、
拖入模块、"组成模块/移动到"操作条）、检查器里的"所属分组"、侧栏与顶栏的"未归属区域"计数、
孤儿 CSS `decomposition-panels.css`。

**文件格式**：`server/project-library` 原本**按模块定义分文件存**（一个模块一个不可变 blob，
清单只记文件名）。没有可拆的粒度之后就退回"一个项目一份 JSON"，
原子性仍由临时文件 + rename 保证。`scripts/export-ue-actors.mjs` 与 `playwright` 无关，
见下面"没做的"。

**改名**：`features/module-editor/` → `features/node-editor/`；
`ModuleEditor` → `NodeEditor`，`ModulePalette` → `BlockPalette`；
`expandModule`/`collapseModule` → `expandNodeScope`/`collapseNodeScope`；
store 的 `expandLogicModule`/`collapseLogicModule` → `expandSubLevel`/`collapseSubLevel`；
`flattenModules`/`FlatModule`/`leafModules` → `flattenNodes`/`FlatNode`/`leafNodes`。
注释里保留对旧名字的引用之处，都写明"这是历史"。

## 考虑过的选项

### 旧项目（`layouts/` 那 7 个）怎么办？

| 选项 | 代价 |
|---|---|
| **不迁移，接受读不出来** ✅ | 那 7 个文件里**一个都没有逻辑拓扑**（全是模块 + 实例），套不上五步流程；迁出来是一堆孤立节点 |
| 写迁移器把实例烘成节点 | 多一套迁移器与测试，产出的东西没有拓扑、没有落位语义 |
| 保留实例回落当兼容层 | 就是**不删模块层**，与这一步的目的直接冲突 |

选第一个。这让 `layouts/*.json` 不再能被 `projectSchema` 解析 —— 这是有意的：
宁可明确报错，也不要读进来一半。

### 分组框（`LogicModule`）到底删不删？

**删。** 它的四个字段各有了新去处：`childScopeId` 早在 1-B 就移到节点上；
`moduleDefinitionId` 是通往模块定义的桥，随模块定义一起消失；
`relativeOrigin` 被 `node.relativePosition` 取代；剩下 `nodeIds` 就只是"把几个区域框在一起"。

而 `FR-03` 早就写过"分组不产生新信息"，`NON_GOALS` 里也写着"不为了以后可能有用留一层"。
一个只画框、不承载任何数据的分组，留着就是让人以为它能干点什么。

代价要写清楚：**画布少了 123 行**，`DecompositionCanvas` 从 409 行降到 286 行，
分组相关的 CSS 也删了 38 行。

### `role-templates.ts` 留不留？

它把 `LogicNodeRole` 映射成一组默认体块尺寸，是**确定性规则**，不是模块件 ——
但唯一的使用者是模块草案，随这一步一起没了。**删掉，并记在这里**：
它是一个"按角色快速起稿"的能力，要做的话应该在**节点**上重做（选中节点 → 按角色给一组
`estimated` 积木），不是复活模块草案。

## 放弃了什么

- **区域分组**（画布上把几个区域框在一起）。这是删模块层里唯一真正损失的用户可见能力。
- **模块级底图与解释文件**（`ReferenceTools` / `interpretDiagram`）。底图能力本身属 P1（FR-10），
  应该在节点上重做。
- **端口对接检查**。它查的是"模块实例拼起来时端口对不对得上"，随实例一起消失。
  UE 计划里仍保留 `assemblyIssues: []` 这个键（类型是空元组），因为
  `scripts/ue_unreal_spawn.py` 与已导出的 `layouts/ue-plan/*.actors.json` 都读它 ——
  但**读成"0 = 检查过了、没问题"是误读**，UE 面板里那一格已经撤掉。
- **按模块分文件保存**。

## 过程中查出来的东西

- **"没有面板引用 ≠ 没人引用"又救了一次**：`ModuleEditor` 看着像模块件，
  其实是**节点几何编辑器**，整个 `features/module-editor/` 一起删会把主流程弄断。
  同类的还有 `module-preview-model`/`module-plan-blocks`（节点缩略图的地基）、
  `project-merge`（通用三方合并）、`disk-baseline`、`duplicateMaterialGroups`。
  这些都在删之前被单独确认过，其中两个是删完编译报错才发现的。
- **`LogicModule.childScopeId` 的旧回落读法**在 `childScopeIdOf` 里留了一个多月，
  这次一并删掉，函数只剩一行。
- **批量拖放的撤销粒度**一度丢失：`editDecomposition` 同时管"排版 + 归属"，
  归属没了之后整个函数被删，于是多选拖动变成"一个节点一条历史，撤销一次只回去一个"。
  现在补了 `moveNodes` 作为批量入口，一次拖动仍是一条历史。
- **3D 预览"可选区域"下拉按积木去重**，一个节点有几块积木就列几次同名项，
  还触发 React 重复 key。改成按 `placements` 列。

## 已知边界与风险

- **`layouts/` 里 7 个旧项目读不出来了**（`projectSchema` 会拒绝）。这是有意的取舍，不是漏洞。
- **`scripts/` 下有 4 个脚本还在按旧模型工作**（`export-ue-actors.mjs`、`validate-blockout.mjs`、
  `generate-diagram-project.mjs`、`build-elysian-rebuild.mjs`）。它们这次**没有一起改**：
  都是离线工具，手写了一套模块/实例模型（有的连应用代码都不 import），
  改它们要从"节点几何"重新推一遍连接求解，是独立的一步。**在修之前不要信任它们的输出。**
- **`docs/rebuild/` 与 `design-log/` 里"模块"仍是历史术语**，按 `PRODUCT_REQUIREMENTS.md` §4 的
  口径，它只在"被取代的说明"里出现。
