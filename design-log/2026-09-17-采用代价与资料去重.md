## 背景

走查 A+B 的模块工作流时，走完整条 agent 链路（准备材料 → 取请求 → 产出草案 → 预览 → 采用），抓到两个"采用之后才发现"的问题。两者都不是崩溃，是**信息该在的时候不在**。

## 采用代价：不能采用后才发现引入了硬错误

### 问题

规范检查只在点「采用」那一刻跑。我采用的草案带一个硬错误——端口放在 x=830，而楼板只到 x=800，**端口悬空**。这个是采用之后才在顶栏看到"3 个问题"的。

预览当时显示的是积木差异（新增 8 / 修改 0 / 移除 0），没有说这版几何在规则上意味着什么。

### 决定

试算一层，**不写入任何东西**：

```
previewModuleDraft(project, draft)    合进去会得到什么项目（含 schema 校验）
        ↓
moduleDraftImpact(project, draft)     对比 前/后 的 validateProject
        ↓
{ introduced, resolved, remaining }
```

面板按严重度着色：干净（绿）/ 只增提示（黄）/ 增错误（红），并列出具体条目。试算不通过时直说"采用会被拦下"，不显示假结论；规范检查未启用时不制造结论（返回全空而不是"没有问题"）。

### 放弃的做法

- **采用时硬拦**：草案带错误就不许采用。太严——设计早期几何本来就不合规，"先摆出来再修"是正当流程。给信息，不给禁令。
- **只在采用的是时候弹确认框**：仍然是"事后"，且打断操作。

## 同名资料

### 问题

项目里有两份 `logic-topology.png`。参考栏里显示完全一样：

```
logic-topology.png  原作用域：根作用域 · 含原图数据，待 agent 核验
logic-topology.png  原作用域：根作用域 · 含原图数据，待 agent 核验
```

我扮演 agent 时**无法判断哪份是当前版本**，只能在 assumptions 里写"两份都未作为尺寸依据"。这对 AI 初始化是直接的质量损失。

### 决定

解析后的资料补三项派生信息（只在上下文与请求里，不落盘）：

```ts
{ contentDigest, variantLabel, origin }
```

- `contentDigest`：有原图取原图指纹，否则取文字指纹。
- `variantLabel`：`同名 1/2` 这样的可引用序号。
- `origin`：资料**真正存放的位置**。

按内容分两种情况，**都不自动取舍**：

| 情况 | 提示 |
|---|---|
| 内容完全相同 | 保留任意一份即可；可在「历史资料管理」移除多余的 |
| 同名内容不同 | 无法判断哪份是当前版本，本次全部保留，请人工确认后删除旧版 |

实测你那两份 `logic-topology.png` **内容完全相同**——所以是真重复，不是版本歧义。系统直接给出了这个结论。

### 放弃的做法

- **按名字自动去重**：同名不同图的情况真实存在，自动删会丢东西。
- **按时间取最新的**：`concept.inputs` 里没有可靠的"哪个更新"信息，猜就是错。
- **静默折叠**：agent 看不到歧义，就会挑一张当作依据，然后声称"已参考结构图"——这正是项目诚实规则禁止的。

## 过程中修掉的两个自己的错误

1. **提示指错了地方**。我原本写"可在资料管理里移除"，但那两份资料存在旧版 `concept.inputs` 里，真正的入口是「历史资料管理」。加了 `origin` 字段后按实际存放位置精确指路。
2. **`MaterialManager` 根本没有删除功能**。提示让人去删，但那里没有删除按钮——等于死路。补了删除（带影响面说明、可撤销）。

**教训**：给出"去哪里处理"的提示时，必须验证那个地方**真的能处理**。

## 已知边界与风险

- `contextDigest` 的算法改了（资料字段改为显式列举，避免把派生字段吃进指纹）。这会让**本次改动之前准备好的请求**变为过期。方向是安全的（拒绝而非误用），但当时在途的请求需要重新准备。
- `origin` 是三值枚举，将来资料归属层级变多（区域级、连接级）时要扩展。
- 去重只做提示，不做清理；项目里长期堆积的重复资料仍需人工处理。
