## 背景

09-13 那轮做出了输入 / 识别 / 拆解 / 构型四个面板，链条完整但**步骤感太重**：用户得按顺序走完，才能开始搭第一个模块。真实制作不是这样的——人想先把教堂内部做出来，再回头看整体。

用户反馈的核心是三条：**拓扑要能持续用**（不是走完就扔）、**上下文要总能看到**、**形态生成要在拼接里自然发生**。

## 决定

主流程收敛成 **逻辑拓扑 ⇄ 拼接搭建**：

```
逻辑拓扑（区域、连接、模块组织）
    ⇅
拼接搭建（模块内部 ⇄ 整体）
```

- **分组并入拓扑**：框选成组、拖入拖出、整组移动都在拓扑画布完成。不再有独立"拆解"页。
- **直接编辑模块**：点「搭建」进入，**不需要先生成实例**。已有白盒直接打开；没有就显示空画布 + 区域清单 + 待实现接口。
- **上下文常驻**：项目提醒条一直在；模块资料栏默认展开，切换模块时正确切换。
- **形态在拼接中确定**：手工搭或看 AI 草案，采用后接着编辑。

## 放弃或推迟了什么

| 放弃的 | 理由 |
|---|---|
| 独立"拆解"页作为主步骤 | 分组本质是拓扑编辑，单开一页只是为了流程好看 |
| 独立"构型"页作为主步骤 | 「套用构型 → 跳到另一阶段编辑」是两段式，打断连续操作 |
| 要求先完成所有区域定位才能建内部 | 全局没定位不该阻止局部设计 |
| 隐藏的资料抽屉 | 上下文要一直看得见，不是点开才有 |
| 把"按角色模板生成"叫作 AI | 它是确定性规则，改名冒充 AI 是欺骗 |

**旧能力保留过渡入口**：拆解/构型页从主导航撤下，但领域能力和数据都留着，历史资料走「历史资料管理」。撤下入口 ≠ 删掉能力。

## AI 初始化的边界（这轮最谨慎的部分）

用户明确要"AI 初始化参考"，但**这个工具不调用模型**。做法是把这条链路拆开：

```
编辑器收集本模块材料（含可读原图）→ ModuleDraftRequest（带双指纹）
    → 本地桥接暂存，显示"等待 agent"
    → 本地 agent 取走、看图、产出 ModuleDraft
    → 编辑器读取、预览、采用（一次可撤销事务）
```

**关键约定**：

- **双基线**：`contextDigest`（相关拓扑 + 资料内容）与 `geometryDigest`（当前几何）。任一变了你就是过期草案，拒绝采用。
- **没有自动模型调用就不显示假进度**。"材料已准备，等待 agent"是诚实状态。
- **出处即身份**：积木用 `provenance`（源 + 特征 ID）绑定区域或链路，**不靠名字匹配**。校验会拒绝伪造身份、重复语义来源、遗漏区域、端口数不对。
- **采用 ≠ 设计完成**。形态单独有确认状态；采用只表示开始使用这版几何。
- **已有手工内容**时先显示替换差异并要求明确确认，不做隐式追加或自动合并。

## 实测发现的问题

一次端到端走查（我扮演 agent 走完整条链路）抓到两处，都属"采用之后才发现"：

1. **草案预览不预告规范检查影响**——我采用的草案带一个硬错误（端口悬在楼板外），是采用**之后**才在顶栏看到。
2. **同名资料无法区分**——项目里有两份 `logic-topology.png`，参考栏和 agent 请求里长得一模一样，我作为 agent 无法判断用哪份。

两项都在 09-17 修掉，见[采用代价与资料去重](2026-09-17-采用代价与资料去重.md)。
