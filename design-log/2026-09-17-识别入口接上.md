# 识别入口接上：主流程五步全部走得到

**日期**：2026-09-17（当日第四次修订）
**状态**：已实现
**相关文件**：`App.tsx`、`ConceptRecognitionBoard.tsx`、`ConceptInputsBoard.tsx`、`concept-inputs.ts`

---

## 这一步做了什么

**接一根线。** 上传面板与候选面板早就写好了、import 了、也渲染了，
但 `store.setConceptPane` **在整个仓库里没有调用者**，所以两个面板都没有按钮能走到。

在 `App.tsx` 的工作区顶部加了一条工作面入口栏：

```
逻辑拓扑 ｜ 输入上下文 ｜ 识别候选
```

它在任何逻辑层都显示，包括分屏里 —— 拼模型的时候也可能要换一张拓扑图。

顺带补了两处：

1. **识别页自己能收图**。候选要落在图上，所以图是识别的前置条件；原来空状态写着
   "先在「输入上下文」里导入范围图"，等于让人先去别处猜。现在识别页自带上传按钮，
   并且**明确说出图是它的前置**。
2. **文案里还活着的"拆解"全部改成"识别"**。拆解这一页早删了，但完整性核对、
   输入包表头、警告文案还在说"不能拆解"，读起来像在指一个不存在的地方。

## 为什么这条线会漏

这是**同一个毛病第二次出现**：

| 时间 | 缺的线 | 表现 |
|---|---|---|
| 上午 | `expandLogicModule` 无调用者 | 双击进节点看不到更深一层 |
| 本次 | `setConceptPane` 无调用者 | 上传图与识别候选打不开 |

两次都是"零件齐全、逻辑完整、有面板、有 import，就是没按钮"。
`NON_GOALS.md` 里那条"不把'能演示'当'已实现'"就是冲这个写的 ——
**面板存在不算做了，界面上走得到才算。**

## 实测走通的链路

在浏览器里跑了一遍完整的，不是只看代码：

```
上传 krat-station-draft.png（1265×805）
  → 同步给本地服务（落盘为合法 PNG，agent 能直接打开）
  → 推一份候选（3 区域 / 2 链路 / 4 条警告）
  → 拉取：图上出现 3 个标记、警告逐条显示
  → 排除一条：标记变淡、勾选框生效
  → 采用：回到拓扑画布，节点带上角色与标高、链路带上类型、识别结果已登记
  → 落位与朝向、3D 预览、UE 计划接着都能用
```

**指纹守卫也试了**：`sample-candidate.json` 基于的是另一份输入的 digest，
拉取后**套用按钮被禁用**并说明"候选基于旧输入，请重新识别"。
这是对的 —— 输入变了就拒绝沿用旧结论，而不是静默采用。

## 边界：识图不在工具里

按 `NON_GOALS.md`，"工具内全自动识图"不做（内置 CV / 多模态 API 工程量大一个量级）。
所以**每次识别都需要 agent 在场**：工具负责"图进去了、候选能核对、采用是事务"，
不负责"不用人也行"。

这不是没做完，是**已经选定的路线**，写进 FR-02 里免得以后被当成缺口重做一遍。

## 已知边界与风险

- **两个面板还没有自动测试**。本次是浏览器实测，没有留下会跑的回归测试。
  这类"有零件没入口"的毛病已经出现两次，值得以后补一个能跑 DOM 的测试
  （当前测试环境是 node，没有 jsdom）。记在 `work-log/NOW.md` 里。
- **候选的位置换算依赖比例标定**。没标定时所有节点都是"尚未定位"，
  展平与导出会把它们按原点处理（界面会点名）。
- **`data/concept/inputs/` 只做暂存**，每次同步整目录重建，不是用户数据。
