# 展平节点几何：3D 预览与 UE 导出改吃同一份来源

**日期**：2026-09-17（当日第三次修订）
**状态**：已实现
**相关文件**：`src/domain/node-geometry.ts`（新建）、`deployment-geometry.ts`、`ue-plan.ts`、`module-preview-project.ts`、`PreviewPanel.tsx`、`ConceptInspector.tsx`、`project-store.ts`

---

## 这一步要解决的问题

从前两次削模块整轮回退的**结构性原因**：3D 预览与 UE 导出都从 `resolveAssembly(instances)` 出发，
而几何挂在 `ModuleDefinition` 上、位置挂在 `ModuleInstance.assemblyTransform` 上。
**删掉模块层 = 这两条路一起断。** 所以它不是"清理"，它是把承重墙换成新墙。

## 决定

新建 `node-geometry.ts`，成为**唯一**的几何来源：

```
节点树 ──展平──▶ FlatGeometry { placements, blocks, unplaced }
                      ├──▶ deployment-geometry ──▶ 3D 预览
                      └──▶ ue-plan ──────────────▶ UE Actor 计划
```

`deployment-geometry` 与 `ue-plan` 不再解析模块与实例，只负责把拿到的值换算成各自的形状。
`resolveAssembly` 保留下来做**端口约束检查**——那件事本来就是关于"组装"的，与几何从哪来无关。

### 坐标：沿层级累加落位

```
世界位置 = Σ(路径上每一级节点的 relativePosition) + 积木在节点里的位置
世界朝向 = Σ(路径上每一级节点的 relativeRotation) + 积木自己的朝向
```

`relativePosition` 因此有了双重身份：**既是节点在父级里的落位，也是它自己那套坐标的原点**。
子层的坐标本来就相对它所属的节点，所以往下走时只需要把那个原点累加进来。

## 考虑过的选项

### 旧项目怎么办？

| 选项 | 代价 |
|---|---|
| **同一个展平函数里回落** ✅ | 两套摆放的代码并存到 1-F；但 3D 与 UE 不必各写一套分支 |
| 立刻写迁移器把实例烘进节点 | 多一个迁移器 + 一套迁移测试；而仓库里 7 个真实项目**根本没有逻辑拓扑**，迁出来是一堆孤立节点 |
| 直接不管旧项目 | 演示项目与示例关卡立刻白屏 |

选回落。**只在整张图一个节点积木都没有时才走实例**——有节点几何的项目完全忽略实例，
否则同一个体块会被算两次。

### 预览里的 Z 用哪个口径？

`blockBaseZ` 已经含了积木自己的 Z，而展平又把它累加了一遍，于是 Z 被算了两次（测试抓到 600 vs 300）。
现在的口径是：**`PlacedBlock.position` 的 Z 是底面标高，XY 是中心**。
口径不一致是刻意的（体块高度是画几何时才关心的），所以写进类型注释里，并在两个消费者里都不再叠加。

## 放弃了什么

- **每个节点不能独立摆自己的子层位置**：子层内容跟着节点走，几何视图里不重复存一份。
  这是 NON_GOALS"同一个事实两个出口"那条的直接应用。
- **没有节点级"整体摆放"了**：旧的整体视图靠实例的 `assemblyTransform` 摆位，
  新模型里位置来自节点的 `relativePosition`，所以摆位这件事回到了检查器的「落位与朝向」里。

## 过程中查出来的四个 bug

1. **同步键把节点 id 写了两遍**。`path` 的最后一段本来就是摆放自己，而 `actorSyncKey` 又单独拼了一次。
   现在路径段只取祖先。
2. **子层的偏移没有跟着父节点转**。父节点转了 90°，子节点还往原来的方向偏。测试断言 1000 却得到 1200。
3. **`flattenNodeGeometry` 把子层算了两遍**：一次顺着节点的 `childScopeId` 递归，一次又显式走了一遍。
4. **换层之后预览不标记为过期**，面板继续显示上一层的几何。现在换层即标记"3D 需要刷新"。

## 已知边界与风险

- **旧项目不会自动长出逻辑拓扑**。`layouts/` 里那 7 个文件仍是"模块 + 实例"的形态，
  靠 `node-geometry` 的回落继续能看，1-F 之后会退化为只读。
- **没有落位的节点按原点处理**。展平如实反映，界面负责报出来（UE 面板与状态栏都会点名）。
  这个选择是有意的：让人看见"这些叠在一起是因为没定位置"，而不是猜为什么少了几块。
- **父级朝向会连子层一起转**，但没有做"子节点反向补偿"。父子都转时结果符合直觉，
  只是要记得检查器的朝向是**相对父级**的。
- `PlacedBlock.position` 的 Z 与 XY 口径不同，这是最容易看错的一处，已写进类型注释。
