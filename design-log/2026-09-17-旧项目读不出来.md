# 旧项目读不出来：把"拒绝"真的做出来

**日期**：2026-09-17（同日晚，接在"删掉模块层"与"删掉识图"之后）
**状态**：已实现
**相关文件**：`app-v2/src/domain/project-schema.ts`、`app-v2/src/domain/persistence.ts`、`app-v2/src/domain/persistence.test.ts`（新）

---

## 发生了什么

删掉模块层之后，`project-schema.ts` 里写了一句话：

> 旧项目文件不会再被静默读成"几何消失了"的半截项目，而是直接被 schema 挡下。

**这句话当时是假的。** `concept` 字段写的是 `logicTopologySchema.optional()`，所以旧文件缺这一格照样通过校验，
读出来是个**一个区域都没有**的合法项目。

代价不是"少读了点东西"，是**静默毁产物**：一个子代理拿旧文件跑 `scripts/export-ue-actors.mjs` 做负例测试，
脚本成功退出 0，把已提交的 `layouts/ue-plan/sunken-sanctum.blockout.actors.json` 从 104 个 Actor 覆盖成空数组。
靠 `git checkout --` 还原。（这轮顺带查出老脚本 `validate-blockout.mjs` 也在对同一个文件打印"全部通过"。）

## 决定

1. **`concept` 改成必填。** 项目里几何是主体，不是可选项。
2. **旧格式在 schema 之前拦，并给人话原因。** `assertNotLegacyProject()` 认出旧格式就抛中文说明
   （"这是模块层删除之前的旧项目文件…旧文件保留作迁移输入"），而不是让调用方拿到一串 Zod 路径。
3. **读入口收成一个。** 草稿恢复、导入文件、打开磁盘项目三条路原来各写各的，
   现在统一走 `persistence.ts` 里的 `parseProject`，两道门都过。

## 判据要按实际文件写，不能按想象写

第一版旧格式判据只认 `structureGraph` 和 `shapes` —— 写完就有 4 条测试里的 2 条当场失败，
暴露出仓库里的旧文件其实有**三个家族**，而且分布和我猜的不一样：

| 家族 | 在哪 | 判据 |
|---|---|---|
| 更早的 LayoutTools 画布 | `data/levels/` 的用户数据 | `structureGraph`（这批还带 `shapes`，但 `shapes` 不在顶层） |
| 模块层模型 | `layouts/*.blockout.json` 大部分 | `modules` / `instances` / `connections` |
| 模块层模型 + 无 `structureGraph` | `layouts/souls-starter-floor-wall.blockout.json` | 只有 `modules` / `instances` / `connections` |

`shapes` 这一条**在仓库里没有任何真文件走得到**：我原本以为它在顶层，实际不在。
留着它是因为更早的格式确实有这一格，但**没有真文件覆盖的判据不能算数** —— 所以测试里用构造文件守它，
并在注释里写明哪条断言是真文件、哪条是构造的。

**教训**：`optional()` 与"被挡下"是两件事。写下"会被拒绝"的时候，要么当场跑一遍，
要么就当没写 —— 这次是靠一个子代理做负例测试才撞出来的，不是靠读代码。

## 已知边界与风险

- 这一改**会让所有旧项目在任何入口都读不进来**（导入、打开磁盘列表）。这是有意取舍，与
  `design-log/2026-09-17-删掉模块层.md` 记的那笔是同一件事的两半：那边记"放弃了什么"，这边记"怎么放弃的"。
- **旧项目仍留在仓库里**（`layouts/` 7 个 + `data/levels/` 3 个用户文件），是 Phase 3 迁移输入，没有被删。
- 迁移器还没写。写它的时候，`assertNotLegacyProject` 就是那批文件的入口 —— 迁移器应当**读旧格式、出报告、写新格式**，
  不覆盖原文件（见 `docs/rebuild/REBUILD_PLAN.md` Phase 3）。
- **旧文件都是合法 UTF-8、无 BOM**（`layouts/` 与 `data/levels/` 都量过）。
  Phase 3 的迁移器不必处理编码探测 —— 别为此加一层猜测逻辑。
  顺带一提：在 PowerShell 里读 `data/levels/` 那几个文件时终端会显示乱码，那是控制台编码，不是文件的问题。
