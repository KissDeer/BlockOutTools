# 削掉模块层，把两张画布嵌合成一张

**日期**：2026-09-17

**相关提交**：`eece321` `38ddd34` `639a8ea`
**取代**：[主流程收敛为两个工作面](2026-09-16-主流程收敛为两个工作面.md) 的"两个工作面"形态

## 背景

09-16 那轮把主流程收敛成 `逻辑拓扑 ⇄ 拼接搭建` 两个工作面，用左上角两个按钮切换。用户走了一遍后提出反对，四条意见：

> 1. 逻辑拓扑图里已经包含了很多信息，那我不用去切这个模块，切模块有点多此一举。
> 2. 我搭建这个模块的时候，你也不给我显示里面到底有几个相关的逻辑东西，重点是我要互相连接。没意义的事情就不做了，**模块不需要了**，就按照逻辑拓扑图的节点进去做。
> 3. 逻辑拓扑图里面可以嵌套逻辑拓扑图……但怎么切换到之前模块里那种拼接搭建的内容？
> 4. 现在是左上角两个按钮切换，但问题在于它是**整个界面的切换**——切过去以后你不知道从属于哪个逻辑节点，也不知道在拼哪个，**更没办法整体观察所有逻辑节点**。

第 4 条是真正的痛点，而且**和模块无关**：换成任何两个顶层页签都会有同样的问题。第 1、2 条是另一个问题：模块这层中间商没有带来价值。

## 决定

### 一、削掉模块层

逻辑节点**自己就是可搭建单元**：

```
逻辑节点
  ├─ 内部是几何 → 叶子：直接在里面搭
  └─ 内部是逻辑 → 复合：里面又是一张逻辑拓扑（可多级）
```

不再有 `拆解 → 分组 → 模块 → 构型` 这条链。几何直接挂节点。

**"模块"这个词在产品里消失**。原来的拆解页、构型页、"搭建"按钮、"放入整体"都随之取消。

### 二、一张画布，层级即导航

- **取消顶层两个页签**。进入节点 = 画布聚焦到那一层，面包屑随时退回。
- 任何时刻都能缩出来看全局；分不清"我在拼哪个"这个问题从根上消失。

### 三、节点内显示两层信息

每个节点内部同时显示：

1. **拼好的 2D 内容** —— 多层嵌套时显示**展平后的最终结果**（小房子 → 带大庭院的小房子 → …）。
2. **它的内部逻辑** —— 里面有几个东西、它们怎么连（小房子 ↔ 大庭院）。

### 四、参考图跟着层级走

| 当前层级 | 旁边显示 |
|---|---|
| 最外层 | 整张地图的逻辑拓扑图 + 氛围图 |
| 进入某节点 | 该节点内部的拓扑图 / 氛围图 / 三视图 |

## 考虑过的选项

### 旧分组（一个模块含多个区域）怎么落

| 选项 | 代价 |
|---|---|
| **每个区域各自成为单元** ✅ | 最彻底、模型最简。代价：原本同模块但彼此无连线的区域（Boss 房 + 中庭）变成两个独立单元，需要补一条连线或嵌一层 |
| 旧模块转成一层嵌套拓扑 | 旧项目结构不丢。代价：多一层包装，和"模块多余"自相矛盾 |
| 先不管旧数据 | 新项目走新模型，旧项目只读 |

选第一个。用户原话是"没意义的事情就不做了"，留一层兼容包装就是没意义的事情。

### 嵌套的内部逻辑能否被多个节点引用

**能复用**。这是 09-13 就确认过的"Scope 可当复用资产（同一个鬼屋用在两张地图里）"的延续。代价是必须保留环检测——已经实现了。

### 界面形态

| 选项 | 代价 |
|---|---|
| **单画布 + 焦点层级** ✅ | 进入节点 = 画布换焦点，面包屑退回。任何时候都能看全局 |
| 画布上就地展开/折叠节点 | 像文件夹树。节点一多画布会失控 |
| 上下分栏（上逻辑、下几何） | 屏幕空间被切两半，两边都看不清 |

### 落地节奏

**分两步**（用户确认）：

- **第一步**：一张嵌套画布 + 节点内显示内容 + 参考图跟层级。模块层暂时还在但不挡路，每阶段都能用、能验证。
- **第二步**：从领域层、UI、数据里删掉模块。

一次到位的代价是中间长期不可用、验证周期长；分两步的代价是会出现"一半新一半旧"的过渡状态。

## 放弃或推迟了什么

- **放弃"两个工作面"这个形态**（09-16 的决定被本轮修正）。数据模型和领域能力继续用，只是操作入口合并。
- **放弃模块作为复用单位**。复用改由"嵌套内部逻辑"承担，粒度更自然（复用的是一个空间，不是一个打包）。
- **放弃"放入整体"这个动作**。节点本来就在地图里，不存在"放"。
- 第二步之前，拆解/构型相关的旧能力仍留在代码里，但不作为主路径。

### "整体观察"的粒度（已定：A + C）

这是本轮唯一需要用户拍板的实现问题，因为它直接决定画布复杂度。

| 选项 | 代价 | 结论 |
|---|---|---|
| **A. 缩出去看上一层** | 小。面包屑能退到整图，任何一层都能看到该层全部节点 | ✅ 选 |
| B. 一屏看到所有层级（地图式缩放） | 中。要做展平几何的缩略渲染 + 性能控制；节点多、几何复杂时缩小后大概率看不清 | ✗ 不值得 |
| **C. 侧边常驻层级树** | 中。多一个面板 | ✅ 选 |

**A + C**：画布保持干净（A 负责"我在哪一层、这层有什么"），侧边一棵可点的层级树负责"全局有哪些东西、哪些已经做了内部"。B 被否掉的理由是收益不明确而代价确定——需要时再单独立项。

## 已知边界与风险

- ~~**"整体观察"到底做到什么程度没有定**~~ → 已定 A + C，见上。
- 节点内同时显示几何 + 内部逻辑，节点尺寸小的时侯会糊成一片。缩略图的信息密度需要实测调。
- 旧的 `ModuleDefinition` / 实例 / 连接数据在第二步要迁移或冻结，迁移规则未定。
- 3D 预览与 UE 导出目前吃的是"实例 + 模块定义"，节点化之后要改成吃"展平后的节点几何"。
- 第一步的层级路径靠"节点 → 所属模块 → 是否有子作用域"推导。第二步削掉模块后，这个推导要改成直接看节点有没有内部。过渡期两套含义并存，是这段代码最容易出错的地方。

## 后来怎样了

**第一步已实现（`639a8ea`）**，实测确认：

| 操作 | 面包屑 | 画布 |
|---|---|---|
| 打开 | `整图` | 逻辑拓扑（9 个区域，节点内显示已拼好的内容） |
| 点层级树「B 站厅主体」 | `整图 › B 站厅主体` | 切到**内部逻辑**（区域 1、区域 2） |
| 再点「区域 1」 | `整图 › B 站厅主体 › 区域 1` | 切到**几何**（体块编辑器） |

两次切换层级树**都在**，全局视图不再丢失；参考栏跟着层级换成「区域 1」的资料。顶层两个页签已删除。

关键实现选择：**层级路径只存节点 id**，当前在哪一层、画逻辑还是画几何，全部由 `resolveLevel` 从拓扑推导。这样拓扑一改，层级自己跟上，不会留下对不上的导航状态；路径失效时退到仍然成立的那一段。

### 实现中发现的两个真问题

1. **两种 id 空间混用**：`openModule` / `openModuleById` 手上是**模块定义 id**，我却当成**逻辑模块 id** 去查，导致从整体摆放进入节点时静默无效。测试抓到了。
2. **层级树在进入节点后被藏起来**——正好复现了这次改动要解决的那个抱怨。它现在常驻两侧。

### 遗留处理

`createDemoProject()` 没有逻辑拓扑，早期项目里也有"没有对应节点的模块"。这类模块用 `detachedModuleId` 单独开一条路径：仍然能编辑几何，但层级停在整图，并明确标为遗留。第二步削模块时这条路径一并去掉。

### 还没做的

- 第二步：从领域层删掉模块（`ModuleDefinition` / 实例 / 连接的数据迁移规则未定）。
- `AssemblyCanvas` 降级成了几何层里的「整体摆放」按钮，第二步要决定它的去向。

### 左侧栏合并（`c2c4404`）

原来区域被列了两遍：一份平铺的模块清单（下面还有"全部区域"折叠），一份层级树；而**层级树一进节点就被藏起来**——两份讲同一件事，活下来的那份还是更没用的那份。

合并后层级树成为区域清单的唯一出口，并吸收了平铺清单独有的信息：

- 每个区域的**进度**（`入口大厅 7` = 已搭 7 个体块），取代"待搭建"标签
- **未归属**标记，取代独立的"未归属区域"段
- 点击仍然跳到能看到它的那一层

`ConceptSidebar` 只留不是区域清单的东西：新增区域、自动排版、链路类型、锁钥、逻辑检查。它自己画的 scope 面包屑也删了——工具栏已经说明"我在哪"，层级树说明"我能去哪"。

**判断依据**：两份清单不是"信息丰富度"问题，是**同一份数据有两个出口**。这类重复不会自己消失，只会让人不确定该信哪一个。
