## 1. 一句话定义

BlockOutTools 是一个本地桌面网页工具：**把手绘的逻辑拓扑图变成可分节点搭建、能 3D 预览、能导进 UE 的白盒关卡。**

它不是通用建筑 CAD，不是外部 LayoutTools 的复刻版，也不是"模块化关卡资产管理系统"。

## 2. 目标用户

作者本人。用 UE + Blockout Tools 插件做魂系关卡白盒。

不需要理解网页内部 ID、UE Python 脚本或 Blueprint 反射细节。默认桌面键鼠，不维护手机端。

## 3. 主流程

```
① 上传逻辑拓扑图
        ↓  识别给出候选，人工核对
② 图上的区域变成逻辑节点
        ↓  双击进入
③ 节点内部拼模型（局部厘米坐标）
        ↓  节点内部还可以是一张逻辑拓扑 —— 回到 ②
④ 3D 预览
        ↓
⑤ 导出到 UE
```

五步。**没有第六步，也没有"模块"这一步。**

## 4. 核心概念（术语表，唯一口径）

| 概念 | 含义 |
|---|---|
| **逻辑拓扑** | 节点 + 链路 + 锁钥。只表达"怎么连通"，不含真实位置 |
| **逻辑节点** | 唯一的容器。内部可以是一份几何、一张逻辑拓扑，**也可以两者同时**（见 §4.2） |
| **链路** | 两个节点之间的关系，带类型、通行方向、锁钥条件 |
| **几何** | 节点内部的体块，落在**节点局部厘米坐标**里 |
| **层级** | 节点嵌节点的深度。路径是一串节点 id |

**"模块"这个词在产品里不存在**，在文档里只作为历史术语出现在"被取代"的说明中。

### 4.1 一个节点装两样东西（2026-09-17 二次修订）

节点**不再是"几何或子拓扑"二选一**。它可以同时持有：

```
逻辑节点
  ├─ blocks        自己的几何（节点局部厘米坐标）
  └─ childScopeId  自己的子逻辑拓扑（下一层节点 + 链路）
```

理由：这两样讲的是同一个东西的两面。**节点是关卡里的一个区域**——它内部有哪些子区域、怎么连通，是逻辑图；它自己长什么样，是拼接图。人在一个区域里干活时，两边都要看着：左边摆子区域和连线，右边拼体块。逼迫二选一，等于进一个区域就必须丢掉一半上下文。

**进入一个复合节点 = 分屏**，左边逻辑图、右边拼接图，两边说的是同一个坐标系，分隔条可拖动。叶子节点（没有子层）不需要分屏，进去就是全宽拼接图。

**唯一坐标原点**：节点的 `relativePosition` 既是它在父级里的落位，也是它自己这套坐标的原点。节点的几何积木、以及它子逻辑层里子区域的落位，**全部相对这个原点**。因此子区域摆在哪里只有一份数据，几何视图不重复存一份位置。

### 4.2 三个"没有了"（相对 Draft 1）

相对 Draft 1，以下概念被整体删除，不是改名、不是降级：

- **模块定义 / 模块实例** —— 节点直接持有几何，中间不再有承载体
- **拆解页 / 构型页** —— 分组不产生新信息，构型就是节点自己的几何
- **多实例复用** —— 复用改由**节点嵌套**承担（复用的是一个空间，不是一个打包）。跨节点复用同一个子树属于后续范围

## 5. 成功标准

顺序即交付优先级。前一条不成立时，后面的都不算数。

1. **一张手绘逻辑拓扑图进去，一张可编辑的逻辑拓扑出来。** 识别不准可以人工改，但不能要求我先手工画一遍节点。
2. **双击节点就能拼模型。** 节点内部用 UE 参数化积木搭建，局部厘米坐标，进出不丢上下文。
3. **节点能嵌节点。** 节点内部是逻辑时，进去就是一层新的逻辑拓扑；层级用面包屑和层级树说清"我在哪"。
4. **3D 预览。** 显式刷新，读的是展平后的节点几何。
5. **导出到 UE。** 稳定同步键，重复导入不产生重叠 Actor。

## 6. 范围

### 6.1 必须有（P0）

| | 能力 |
|---|---|
| 入口 | 上传逻辑拓扑图 → 候选节点 → 核对 → 采用。识别是一次性**批量导入** |
| 兜底 | 手工增删改节点与链路；识别不参与后续编辑 |
| 节点几何 | 节点内搭建，局部厘米坐标；节点同时是它在父级里的落位，也是这个坐标系的**原点** |
| 嵌套 | 节点内部是逻辑拓扑，可多级；**几何与子拓扑在同一个节点上并存**，进入后分屏同时看两边；复用同一个子树属于后续范围 |
| 3D | 一张画布 + 一个预览面板，读展平几何 |
| UE | 展平导出，同步键 `projectId / 节点路径… / 节点放置 id / blockId` |
| 数据 | 单文件 JSON + 稳定 ID + 本机草稿 |

### 6.2 显著提效（P1）

参考图跟着层级走（进入某节点就看该节点的资料）；规范检查定位到节点；导出的 dry-run 差异摘要。

### 6.3 明确不做

见 [NON_GOALS.md](NON_GOALS.md)。**那份清单是本文的组成部分，不是附录。** 任何人想把里面的条目拉回范围，必须先改那份文件并说明重新评估的条件。

## 7. 产品原则

1. **拓扑图是一次性入口，不是长期数据源。** 识别产出候选、你确认、系统采用 —— 之后拓扑的唯一事实来源就是节点列表。不维护"图片"和"节点"两份都在用的状态，那必然长出一个没人用的面板。
2. **一张画布，层级即导航。** 没有顶层页签。进入节点 = 画布换焦点——换成任何两个顶层页签，都会丢失"我在哪个节点里"。
3. **节点是唯一容器。** 任何"节点和导出之间还有一层"的设计都要先问：这一层产出什么独有信息？答不出来就不加。
4. **三套坐标不能混。** `graphPosition` 只是画布排版，无语义；**节点局部厘米**是节点内部坐标；**世界坐标**只在展平和导出时产生。
5. **指纹咬合。** 拓扑 / 上下文 / 几何各有 digest，下游产物必须携带它依据的 digest，漂移就拒绝，不静默沿用。
6. **出处不靠名字。** 积木用 `provenance`（源 + 特征 ID）表达"来自哪个区域或链路"。
7. **候选先预览、可取消、采用是一次可撤销事务。**
8. **不假装看过图。** 缺原图、比例未标定、方位未知，都写进 `assumptions`。
9. **四种状态不能互相掩盖。** "逻辑连通" ≠ "空间已对接" ≠ "形态已确认" ≠ "玩法已验证"。

### 8.1 09-17 的决定只落地了一部分（开工前必读）

`design-log/2026-09-17` 那篇写"第一步已实现"，实测结论要更严格：

| 那篇说的 | 实测 |
|---|---|
| 一张画布 + 层级导航 | ✅ 已实现，层级树常驻、面包屑可用 |
| 节点内显示已拼好的内容 | ✅ 节点缩略图能看到 |
| **削掉模块层** | ❌ **未做**。`LogicNode` 只有一个 `moduleId` 指针，几何挂在 `ModuleDefinition` 上 |
| **两张画布合一** | ⚠️ **未完成**。主画布之外仍有一个独立的 Konva 几何编辑器，只在进入节点后出现 |

**当前数据模型的真实形态：**

```
LogicNode ──moduleId──▶ ModuleDefinition ──▶ Block[]
                              ▲
                              │ definitionId
                       ModuleInstance ──▶ assemblyTransform ──▶ 3D 预览 / UE 导出
```

这意味着两件事，必须在动手前认清：

1. **`LogicNode` 不能直接持有几何**，所以"在节点里拼模型"在数据模型上无处安放。
2. **3D 预览与 UE 导出是挂在模块实例上的。** 删掉模块层 = 这两条路一起断。

前两次削模块的尝试都因此回退（详见 [FUNCTIONAL_REQUIREMENTS.md](FUNCTIONAL_REQUIREMENTS.md) 的 FR-11 与 [REBUILD_PLAN.md](REBUILD_PLAN.md)）。**它们不是预算问题，是顺序问题**：先删承重墙，再想房子怎么盖。

### 8.2 因此的交付顺序（与"清理路线图"相反）

**先把主流程在节点模型上跑通，再删模块层。**

```
1. 本文与 NON_GOALS 冻结范围            ← 不做这一步，后面每步都被旧需求拉回去
2. LogicNode 加 blocks + childScopeId   ← 从调用方最多的文件倒着改
3. 3D 预览 + UE 导出改吃展平节点几何     ← 这一刀切下去，"删模块就白屏"的绑定永久解除
4. 节点内嵌节点的导航打磨
5. 模块层才删                            ← 此时它是没有承重的隔墙
```

识别（成功标准 1）在 2–3 之后、5 之前插入；在那之前手工画节点是唯一的兜底路径。
