# 产品需求

状态：`Draft 1`

## 1. 产品定义

BlockOutTools 是面向 Unreal Engine 关卡白盒制作的本地桌面网页工具。它不是通用建筑 CAD，也不是外部 LayoutTools 的复刻版。

它要解决的核心问题是：关卡设计师能把楼层或区域制作成可独立编辑、移动和复用的模块，在关系画布上组织模块连接，检查三维空间与可走性，再以可重复、可核对的方式同步到 UE。

## 2. 目标用户

主要用户是使用 UE 和 Blockout Tools 插件制作关卡白盒的关卡设计师。默认使用桌面键鼠，不维护手机端。

用户具备关卡结构、尺寸和路线设计能力，但不应被要求理解网页内部 ID、UE Python 脚本或 Blueprint 反射细节。

## 3. 成功标准

重做版成功必须同时满足：

1. 用户能从首页进入无限画布，新建模块并进入模块内部完成白盒搭建。
2. 同一模块可被多个实例复用，模块内部改动能确定性地反映到所有实例。
3. 出入口作为普通可编辑积木放置；返回外部后可见数量、位置和朝向。
4. 连接关系可读、可编辑，但不会因为关系图排版而改写实际模块数据。
5. 3D 预览和 UE 导入使用同一份规范化几何，不出现“网页看着对、UE 不对”的第二套解释。
6. 同一项目重复导入 UE 不生成重叠 Actor；改名或临时选择变化不破坏同步身份。
7. 项目、模块和连接可以本地保存、重新打开、进入 Git，并能处理常见合并冲突。
8. AI 只能通过受校验的领域命令操作项目，和人工编辑共享积木、参数、撤销与验证规则。

## 4. 核心工作流

1. 打开或新建项目，首页默认显示无限画布。
2. 新建模块、导入模块文件或复用已有模块定义。
3. 进入模块内部，用 UE 参数化积木搭建地面、墙、门、楼梯等内容。
4. 像放置其他积木一样放置模块出入口，设置位置、旋转、名称和局部高度。
5. 返回无限画布，摆放模块实例并用指定连接形式连接出入口。
6. 手动展开并刷新 3D 预览，检查模块、层高、朝向和几何连续性。
7. 运行白盒规范检查，修正通行、门洞、楼梯或坡道问题。
8. 保存项目；需要协作时提交项目清单和模块文件到 Git。
9. 执行 UE dry-run，检查新增、更新、保留、删除和冲突。
10. 用户明确确认后 Apply；工具不自动保存 UE 地图。

## 5. 产品范围

### 5.1 P0 核心

- 项目和模块分文件保存。
- 无限画布模块关系图。
- 模块内部二维编辑器。
- Blockout Tools 参数化积木及少量非导出标注对象。
- 出入口与类型化连接。
- 可收起、手动刷新的 3D 预览。
- 白盒尺寸与可走性规范。
- 完整撤销/重做和 UE 接近的桌面操作。
- AI 领域命令接口。
- UE dry-run、增量 Apply 和 UE 回读。

### 5.2 P1 生产效率

- 模块模板库、搜索、标签和缩略图。
- 项目级批量规范修复建议。
- 选择性 UE 同步和 Actor 差异详情。
- Git 友好的逐字段冲突展示。
- 图片分析结果导入为候选模块和连接，而不是直接覆盖项目。

### 5.3 P2 可选增强

- 关系图自动整理。
- 设计审阅标注和只读分享包。
- PNG/SVG 关系图导出。
- 性能统计、规模诊断和大型项目分区加载。

## 6. 明确非目标

- 不再一比一复刻外部 LayoutTools。
- 不做移动端或触屏版。
- 不重做通用 Polygon、布尔运算、实体图标、通用路网、步行测量、语言主题等外围功能，除非以后有真实白盒用例重新立项。
- P0 不提供 FBX、GLTF、OBJ 等独立 3D 生产导出；UE 是主要三维落地目标。
- 不把 3D 预览建设为独立建模器。
- 不让 AI 操作 DOM、模拟鼠标或绕过参数 Schema。
- 不自动保存 UE 地图，不修改非本工具拥有的 Actor。
- 不在近期实现连接器几何求解。

## 7. 产品原则

- UE 数据优先：能导入 UE 的对象必须有明确 Blueprint 类型和参数契约。
- 一个事实来源：2D、3D、AI、保存和 UE 转换读取同一领域模型。
- 安全可预览：外部写入必须先产生可读 dry-run。
- 身份稳定：名称和显示顺序不是对象身份。
- 模块优先：楼层或区域是独立可复用资产，而不是单个巨大画布中的临时分组。
- 桌面效率优先：减少面板切换，保留专业编辑器熟悉的选择、变换和快捷键。
- 旧数据可迁移：兼容应通过导入器完成，不把旧架构继续带入核心。
