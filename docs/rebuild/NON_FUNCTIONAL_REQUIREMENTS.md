# 非功能需求

状态：`Draft 1`

## NFR-01 性能

P0 性能验收数据集：100 个模块实例、200 条连接；单个正在编辑的模块最多 1,000 个积木；3D 场景最多 10,000 个展开部署几何。

- 无限画布常规平移和缩放目标不低于 45 FPS。
- 单模块移动、旋转、缩放和框选的可见反馈不晚于下一帧；命令提交在 100 ms 内完成。
- 5 MB 项目增量保存目标在 1 秒内完成，保存不阻塞画布输入。
- 10,000 个部署几何的手动 3D 刷新目标在 3 秒内完成，稳定交互不低于 30 FPS。
- 超出基线时允许降级显示，但必须提示规模瓶颈，不得无响应或静默丢对象。

性能数字在 Phase 0 用目标 Windows 机器实测校准；调整必须记录测试硬件和原因。

## NFR-02 可靠性与恢复

- 正式文件写入使用校验后的临时文件和原子替换。
- 自动恢复草稿与正式项目分离；恢复前显示时间、项目和差异摘要。
- 每个用户命令是原子事务：全部成功或全部失败。
- 撤销和重做不得改变稳定 ID，不得跳过 AI 或合并命令。
- Schema 迁移始终保留原文件，并生成可读迁移报告。
- 浏览器刷新、服务重启和 UE MCP 断开不能破坏磁盘项目。

## NFR-03 UE 写入安全

- 本地服务默认只监听 `127.0.0.1`。
- UE Apply 只接受服务端保存的、未过期的 dry-run 计划，不接受浏览器直接提交任意 Python。
- 项目身份、`.uproject`路径、目标地图和桥接拥有范围必须在服务端再次核对。
- AI、导入文件和页面内容都不能提供可直接执行的 UE Python。
- 删除操作默认关闭，并在 Apply 前单独显示数量和 Actor 列表。
- 日志记录计划和错误，但不记录 API Key、授权头或完整个人路径之外不必要的用户数据。

## NFR-04 文件与输入安全

- 文件 API 限制在用户明确打开的项目目录和允许的扩展名中，拒绝目录穿越。
- 所有 JSON、AI 命令和 UE 回读先做大小限制和 Schema 校验。
- 不加载项目内任意脚本、HTML 或远程资源。
- 图片导入只作为数据输入，不执行元数据中的命令或链接。
- 本地 API 对写入使用会话令牌或等价的同源保护，避免其他网页调用 UE 桥接。

## NFR-05 可维护性

- `domain`保持纯 TypeScript，不依赖 DOM、React、Canvas、Three.js 或 UE。
- 所有状态变化经命令进入，禁止界面组件直接改深层项目对象。
- 每个可部署积木的 2D、3D 和 UE 行为由同一 Schema/适配定义。
- 新增 P0 功能必须同时增加需求编号、测试和用户文档。
- 不允许把第三方画布库的节点对象直接序列化为项目格式。
- 外部依赖需有明确用途、许可证和锁定版本；不为单个简单工具引入大型依赖。

## NFR-06 兼容范围

- 首要运行环境是 Windows 11、当前 Chromium 内核和 Node.js LTS。
- UE 基线是用户项目 `E:\Project\MYMY`与已盘点的 Blockout Tools 插件版本；路径属于本机配置，不写入可共享项目文件。
- 桌面最低设计视口为 1280x720；不维护手机端。
- 旧 LayoutTools JSON、旧 `structureGraph`和旧 UE 标签通过迁移器兼容，不要求新运行时兼容旧 DOM 或 Store。

## NFR-07 可诊断性

- 保存、迁移、AI 命令、3D 重建和 UE 同步具有操作 ID 和结构化结果。
- 用户界面显示可行动错误：失败对象、阶段、原因和建议下一步。
- 开发日志可关联一次操作，但默认不输出整个项目、模型提示或敏感配置。
- 3D 空场景、Schema 缺失、计划过期和同步身份重复必须成为显式错误，不能只留控制台警告。

## NFR-08 可用性

- 所有核心命令可通过可见控件完成，快捷键只是加速手段。
- 焦点、选中、锁定、隐藏、仅标注和可部署状态必须视觉可区分。
- 方向、错误和连接类型不能只依赖颜色。
- 图标按钮有工具提示和可访问名称；键盘焦点不被画布无条件截获。
- 长时间操作显示进度并允许安全取消；取消不提交部分事务。
