当前实现的是“校准底图 + 可审查解释数据 + 确定性积木生成”。没有自动识别所有图片的承诺；原图未给出的高度、遮挡结构和比例仍须确认。

## 按输入选择方法

| 输入 | 当前用法 | 精度边界 |
| --- | --- | --- |
| PNG/JPG/WebP 平面图 | 每模块导入底图，用已知线段像素长度/真实厘米校准，原点与角度对齐后描图或写解释数据 | 比例误差与原图像素误差会传递到结果 |
| SVG/DXF/矢量 PDF | 保留原文件；按单位提取路径/标注写解释数据，另导出图片作叠加底图 | 尚无原生解析器；不能把渲染像素当原矢量测量精度 |
| 扫描件 | 先校正倾斜和透视，再校准，人工核对图例/文字 | 尚无 OCR/自动透视校正 |
| 多层展开路线图 | 分模块校准，同字母/编号连接；单独填写实际高差 | 纸上模块间距不是实体世界间距；交叉线不自动生成节点 |
| 透视/轴测/游戏截图 | 使用已知尺寸、多视图或明确设计假设确定平面尺寸与高度 | 单张图不能唯一恢复遮挡和深度，标记 estimated |

## 操作

1. 进入模块，“图纸底图”导入图像。原图嵌入模块数据，随项目和模块保存。
2. 填同一已知线段的像素长度与厘米长度，应用校准；用原点和旋转对齐。每个模块独立保存比例，
   标注图例。重新校准只改底图，不擅自缩放已有积木。
3. 可手工按底图摆放积木，也可导出解释模板填入结构数据。
4. 读取解释 JSON 后显示新增/修改/移除旧分块/保留数量及候选坐标，接受当前模块是一个可撤销事务。
5. 检查楼板覆盖、墙体真实开口、楼梯落脚点、端口支撑，再看组装约束与三维剖切。

## 解释 JSON v1

页面导出的模板带当前 sourceId 和 moduleId，必须保持不变。每个 elements 条目有稳定 id、name、kind，可附 confirmed 与 note。改名不改 id；不要使用所有元素在数组中的序号作为身份。

所有二维点使用**原图像素坐标**；高度、厚度、墙高、楼梯宽度、端口宽度均使用**厘米**。底图原点表示图像左上角在模块内的 XY，正角度遵循网页坐标。基准使用行走表面 Z。

```json
{
  "schemaVersion": 1,
  "sourceId": "使用页面导出的值",
  "moduleId": "使用页面导出的值",
  "elements": [
    { "id": "court-floor", "name": "庭院楼板", "kind": "floor", "polygon": [[0,0],[400,0],[400,300],[0,300]], "holes": [[[150,100],[250,100],[250,200],[150,200]]], "elevation": 0, "thickness": 40, "confirmed": true },
    { "id": "north-wall-west", "name": "北墙西段", "kind": "wall", "start": [0,0], "end": [150,0], "elevation": 0, "thickness": 30, "height": 300 },
    { "id": "court-stairs", "name": "庭院内部楼梯", "kind": "stairs", "lower": [300,50], "upper": [300,250], "lowerZ": 0, "upperZ": 200, "width": 160 },
    { "id": "north-port", "name": "北口", "kind": "port", "position": [200,0], "elevation": 0, "rotation": -90, "width": 150 },
    { "id": "route-note", "name": "红色路线", "kind": "route", "points": [[200,0],[300,50],[300,250]] }
  ]
}
```

楼板当前支持正交多边形和孔洞，通过精确矩形分区铺满，不用外接矩形填洞；复杂轮廓超限或非正交斜边会拒绝，需先拆分或手工编辑。墙使用任意角度线段，超过 360cm 自动拆短段并允许 2cm 接缝重叠。墙上门洞需明确断开墙线，不能只叠一个端口在实体墙上。

楼梯按 lower/upper 平面点和上下行走高度生成；固定两端，不凑尺寸。踢面/踏步标准取项目规范，空间不足拒绝生成。路线只作为解释数据保存，不生成墙或额外端口。模块之间连接仍由用户在无限画布连接既有端口。

生成积木保存 sourceId、featureId、confirmed/estimated 和 note。只有校准和特征尺寸均确认，状态才为 confirmed。特征在原解释文件中缺席时保留旧对象，不擅自猜删除；明确重新生成的同一特征若分块改变，会列出并移除该特征的旧分块，避免楼板孔洞被旧块重新填满。增删其他特征不改变既有特征身份；同一特征内部拓扑改变可能改变它的分块 ID，接受前检查数量变化。

## 命令行复用

```powershell
node scripts/generate-diagram-project.mjs base.blockout.json module-interpretation.json candidate.blockout.json
```

基础项目需已保存目标模块底图。命令编译并复用网页同一领域生成器，输出新的候选文件与诊断，拒绝覆盖输入及已有输出。可把原文件、解释 JSON、候选和最终项目一起交给 Git 管理。不写 UE。

## 验收边界

当前自动检查门尺寸、台阶踢面/踏步、明确楼板模块中的端点宽度支撑和 Box 净空。仍需人工看底图叠加、完整路线和非 Box 障碍；最终 UE 碰撞、台阶形态、导航可达性须通过实际 Editor 回读和角色测试。闭环残差为零不代表能走。
