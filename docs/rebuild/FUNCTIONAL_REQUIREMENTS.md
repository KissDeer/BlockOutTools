## FR-01 项目文件与草稿（P0，已实现）

- 项目是一个 JSON 文件，含项目身份、逻辑拓扑、节点几何、设置。
- 新建、打开、另存使用明确的本地文件位置。
- 编辑后自动保存可恢复草稿；正式文件写入原子化，中断不产生半个 JSON。
- 页面重开和服务重启后恢复最后项目与最后视图。
- 未保存 / 保存中 / 已保存 / 保存失败状态清晰可见。
- 旧 LayoutTools JSON 只能通过"导入旧项目"进入，不成为运行时模型。

**验收**：改动后重开浏览器，内容与视图一致；写入中断时仍能恢复上一个有效版本。

**已知问题**：参考图以 base64 存在项目 JSON 里，每次编辑防抖 350ms 会把**整份项目含图**序列化进 localStorage。图一多必卡。修法是把图片移出项目文件，按内容摘要分文件存放。

## FR-02 拓扑图识别导入（P0，**入口待重做**）★ 主流程入口

**这是产品定义的第 1 条成功标准，目前是主流程唯一没有闭环的一步。**

- 用户上传逻辑拓扑图（PNG / JPG / WebP）。
- 识别产出一组**候选节点与候选链路**，覆盖在原始图片上，节点位置与图上位置对应。
- 候选**必须先预览、可逐条勾选排除、可拖动修正位置**；采用是一次可撤销事务。
- 采用前给出规范检查的试算影响；采用零写入取消。
- 识别结果携带它依据的输入指纹；输入变了，旧候选标记过期并拒绝采用，不静默沿用。
- 图片只作**一次性入口**：采用之后，拓扑的唯一事实来源是节点列表，图片退化为参考资料。**不维护"图片"和"节点"两份都在用的状态。**

**验收**：一张手绘拓扑图上传后能在界面上看到候选、修正、采用；采用后节点可正常编辑与嵌套。

### 状态（2026-09-17 晚）

**"上传 → 手动同步给本地服务 → agent 读图 → 拉取候选"这条路线已被用户放弃**，
理由是太绕：一次识别拆成四步，其中两步要人离开工具去别处操作，还要 agent 全程在场。
见 [NON_GOALS.md](NON_GOALS.md) 第二节。

**工具侧那半仍然可用，也有价值**：候选的模型、校验、图上叠加、逐条勾选、拖动修正、
按指纹拒绝沿用 —— 这些与"图从哪来"无关，换路线时可以直接复用。
已经实测走通过的链路（上传图 → 同步落盘 → 拉候选 → 逐条核对 → 采用 → 节点进画布）
留给以后参考，端口是 `POST/GET /api/concept/{inputs,candidate}`。

**还没做的决定**：新路线是什么（工具内接多模态 API？别的方式？）。
在定下来之前，这一条**不再投入**，但也不从需求里删掉 —— 它仍然是主流程的第 1 步。

## FR-03 逻辑拓扑编辑（P0，已实现）

- 节点：新增、改名、角色、楼层、备注；`graphPosition` 只是画布排版，无语义。
- 链路：两端方向、10 种链路类型、通行方式（双向 / 单向 / 一次性）、锁钥条件。
- 锁钥：取得位置、解锁哪些链路。
- 画布：平移、缩放、框选、多选、适应全部、自动排版、四向连接点。
- 图上的排版坐标**永不参与**几何、3D 或 UE 计算。

**验收**：移动画布上的节点只改变排版，不改变 3D 与 UE 结果。

**已删除**（不再是本需求的一部分）：框选成组、拖入/拖出模块、模块标题整组移动、模块徽标与配色、未归属区域提醒。分组不产生新信息。

## FR-04 节点几何（P0，已实现）

- **节点直接持有几何**：`LogicNode.blocks: Block[]`。不再有 `moduleId` 指针（旧数据靠回落读，1-F 删）。
- 双击节点进入其内部；已有几何直接打开，不重建、不重置。**复合节点进去是分屏**（左逻辑图 / 右拼接图，见 FR-05），叶子节点是全宽拼接图。
- 节点内部的 `relativePosition` **同时就是它在父级里的落位**，也是节点自己这套坐标的原点；`relativeRotation` 是它自己那套坐标的朝向。两者都能在区域检查器的「落位与朝向」里直接改。
- UE 参数化积木目录（Box / Doorway / Stairs Linear / Port）与参数 Schema 不变。
- 支持单选、多选、框选、移动、旋转、缩放、复制、粘贴、删除、对齐、分布。
- `W/E/R` 切换移动、旋转、缩放；网格吸附可临时关闭；数值输入只提交一个历史命令。
- 撤销/重做覆盖所有编辑命令、属性修改与草案采用。

**验收**：连续执行 20 个混合操作后逐步撤销到初始状态，再完整重做，数据和画面一致。

**落地情况（2026-09-17）**：字段、几何编辑、落位编辑、展平都已经在节点上跑通。
**没有落位的节点会被报出来**（状态栏与 UE 面板点名），因为不报的话多个区域会叠在原点，看起来像少了几块。

## FR-05 节点嵌套（P0，部分实现）

- 节点内部**可以同时**是一份几何和一张逻辑拓扑（2026-09-17 二次修订，见 [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md) §4.1）。不再要求二选一。
- **进入复合节点 = 分屏**：左边这一层的逻辑图，右边这一层的拼接图，两边同一个坐标系；分隔条可拖动，比例记进项目与最后视图。叶子节点进去是全宽拼接图，不分屏。
- 节点的 `relativePosition` 既是它在父级里的落位，也是它自己这套坐标的**原点**：节点自己的积木、以及子逻辑层里子区域的落位，全部相对这个原点。
- 进入复合节点 = 画布换焦点到那一层；面包屑与层级树常驻，任何时刻能缩出去看全局。
- **禁止自包含**：直接或间接包含自己必须报错。
- 深度不设硬上限，但要有递归深度护栏。
- **跨层直连不做**：跨层连接必须经边界逐层落地。
- **复用同一个子树暂不做**（见 NON_GOALS）：嵌套是一棵树，不是图。因此**一个子作用域只能属于一个节点**——`childScopeId` 从 `LogicModule` 移到 `LogicNode` 时，顺带把原来的多对一改成一对一。

**验收**：两级嵌套跑通（大区域 → 子区域），进复合节点两侧都能编辑；构造一个自包含引用被拒绝；面包屑退到任一层都正确。

**当前状态**：层级导航（`resolveLevel` / `levelPath` / 层级树 / 面包屑）已实现，"进入节点"的**读**一侧可用。但有两个缺口：

1. **"把节点展开成子逻辑层"没有界面入口。** `store.expandLogicModule` / `collapseLogicModule` 在全仓库无调用者——和 `setConceptPane` 是同一类毛病。所以子作用域在界面上造不出来。
2. **画布只画一半。** `App.tsx` 目前是 `geometryLevel ? 几何编辑器 : ConceptCanvas` 的二选一，要改成分屏。

`childScopeId` 现在挂在 `LogicModule` 上（`concept-scopes.ts:238-239` 从这里推导"这一层是逻辑还是几何"）。FR-04 落地时它要移到 `LogicNode`，这段推导跟着改。**这是过渡期最容易出错的地方**——两套含义并存，所以读取必须收敛到一个裁决点。

## FR-06 3D 预览（P0，已实现）

- 右侧可收起窗口，默认收起；只有用户显式点击刷新才重建场景，普通编辑只标记"需要刷新"。
- 支持轨道旋转、平移、缩放、聚焦选择、重置视图、平面剖切。
- 读与 UE 转换**相同的规范化几何**，不出现"网页看着对、UE 不对"的第二套解释。
- Stairs、Doorway 等参数化类型按 Schema 重建，不退化为占位 Box。
- 只在节点几何层看局部，在逻辑层看整体已搭建的部分。

**验收**：相同项目的 3D 包围盒、层高、朝向与 UE 计划在容差内一致。

**落地情况（2026-09-17）**：几何已经改成从 `flattenProjectGeometry(snapshot)` 取，
再交给 `buildDeploymentGeometryFrom`。`resolveAssembly` 只用来数端口约束残差 ——
那是**组装**的检查，与几何来源无关。换层时面板会标记"3D 需要刷新"，
不再继续显示上一层的几何。

## FR-07 UE 导出（P0，部分实现）

- 导出展平后的节点几何为 Actor 计划：`syncKey`、`label`、`blockType`、`blueprintClassPath`、`location`、`rotation`、`parameters`。
- 同步键为 `projectId / 节点路径… / 节点放置 id / blockId`；**标签名与语义保持不变**，UE 侧脚本一行都不用改（它把那一段当不透明字符串用）。
- 同一项目重复导出不产生重叠 Actor；改名不改变同步键。
- 单位与坐标映射明确：领域模型统一厘米；网页 `X`→UE `X`，网页 `Y`→UE `-Y`，平面旋转→负 UE Yaw。
- 当前只生成本地计划，不连接 Editor、不 Apply、不回读。

**验收**：同一项目连续导出两次结果一致；重命名节点后同步键不变。

**落地情况（2026-09-17）**：`buildUEDryRunFrom(project, geometry)` 与 3D 预览吃同一份 `FlatGeometry`。
**没有落位的区域会在面板上被点名**，因为它们会被按原点处理、叠在一起。

**一致性风险**：`scripts/export-ue-actors.mjs` 自带一整套 `CONNECTION_RULES` 和求解函数，注释写"与 app 内 ue-plan.ts 语义一致"，但**没有测试锁住这个一致性**。要么合并成一份，要么补一个交叉校验测试。

## 交付纪律

以下三条来自已经发生过的失败，不是通用建议。

1. **先确认预算再开工，一次只做一件事。** 两次削模块整轮回退，原因相同：没确认预算就开了工，而且先改领域模型——那是唯一没有"做一半停下"余地的一步，一改下去全仓库同时红。
2. **"没有面板引用"不等于"没人引用"。** 删退役面板时顺手删了背后的领域件，结果画布编译不过——成组界面还在用。删之前查整个仓库，不是 UI 层。
3. **每步都要能编译、能跑测试。** 184 个测试是资产，不是负担。任何一步之后测试变红，就是这一步切错了。
