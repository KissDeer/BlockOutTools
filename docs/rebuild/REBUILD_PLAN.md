# 重做计划

状态：`实施中 · Phase 0 已达到退出条件`

## 1. 重做策略

采用旁路重做，不在现有 vendor 宿主上继续叠加功能。旧应用在迁移完成前保持可运行和只读参考；新应用拥有独立入口、领域模型和测试。

不从旧 DOM 或压缩 Store 复制内部结构。只复用经过确认的资产：UE 参数化 Schema、图标、示例关卡的设计意图、现有测试数据和已验证的坐标结论。

## 2. 建议技术边界

- TypeScript + Vite 作为应用基础。
- React 负责工作台界面；状态使用显式命令和事务 Store。
- 无限关系画布使用成熟节点图组件，不自研缩放、选区和连线基础设施。
- 模块二维编辑使用成熟 Canvas/SVG 场景库，领域模型与渲染节点分离。
- Three.js 只负责预览，几何由领域层提供。
- Zod 或等价 Schema 库负责文件、AI 命令和 HTTP 边界校验。
- Node 本地服务负责文件系统和 UE MCP 桥接；浏览器不直接持有工程写权限。
- Vitest/Node Test 覆盖领域逻辑，Playwright 覆盖真实桌面流程。

具体库在实现前用一个小型技术验证确定，不能让库的节点模型变成项目数据模型。

## 3. 目录与依赖边界

建议新代码放入独立 `app-v2/`，至少划分：

```text
app-v2/
  domain/       # 纯数据、命令、历史、验证、迁移
  editor/       # 无限画布和模块二维编辑适配
  preview/      # Three.js 几何与交互
  ue/           # dry-run、计划、脚本和回读
  ai/           # 命令 Schema、差异和模型适配
  server/       # 本地文件与 MCP HTTP 边界
  tests/
```

`domain`不得依赖 React、Canvas、Three.js、DOM 或 UE。预览和 UE 都消费相同的规范化部署几何结果。

## 4. 实施阶段

### Phase 0：需求冻结与技术验证

- 用户确认本目录的范围取舍。
- 用 Box、Stairs Linear、Doorway 和 Port 验证二维编辑、3D 和 UE 数据闭环。
- 确定画布库和性能边界。

退出条件：四种对象在同一领域模型中完成保存、撤销、3D 和 dry-run；没有 vendor 依赖。

完成情况（2026-09-01）：`app-v2/`已用 React Flow、Konva、Three.js、Zustand 和 Zod 完成独立技术验证。Box、Doorway、Stairs Linear 和 Port 可建立、编辑、保存、撤销、三维展开并生成本地 UE dry-run；同步键使用`projectId/moduleInstanceId/blockId`，Port 不进入部署几何。自动测试、类型检查、生产构建和 `1280x720`真实浏览器回归通过，Three.js 截图像素与轨道交互已验证。UE Apply、AI、模块分文件和完整 15 类目录仍按后续阶段推进。

### Phase 1：项目、模块和内部编辑

- 项目清单与模块文件。
- 命令历史、自动保存和恢复。
- 模块内部画布、选择、W/E/R、吸附、对齐和参数检查器。
- 完整参数化目录和 Port。

退出条件：可以只靠新应用制作并重开一个单模块白盒。

### Phase 2：无限画布与 3D

- 模块定义/实例、关系图、连接折线和八类连接语义。
- 可收起 3D 预览和项目检查。
- 复用实例展开和同源几何验证。

退出条件：多模块项目能保存、重开、预览和通过规范定位问题。

### Phase 3：UE 增量闭环

- 稳定三段身份、dry-run、Apply、删除保护、回读和迁移旧标签。
- 真实 MYMY 地图验证，覆盖创建、更新、复制、删除和重复 Apply。

退出条件：重复 Apply 无重叠，目标地图回读与项目一致；失败不会留下半成品。

### Phase 4：AI 与图片输入

- AI 命令协议、差异接受和批量历史事务。
- 图片观察 -> 候选命令 -> 用户逐模块接受。

退出条件：AI 与人工操作走相同命令和验证，不能绕过 ID、Schema 或撤销。

### Phase 5：迁移和切换

- 导入现有示例及用户项目。
- 对比旧新项目的模块、几何、连接、规范和 UE 结果。
- 新入口成为默认，旧宿主转为归档参考。

## 5. 质量门槛

- 所有 P0 需求有稳定编号和验收证据。
- 领域层关键逻辑至少覆盖：ID、命令事务、撤销重做、模块实例展开、Schema、规范、合并和 UE 计划。
- 浏览器覆盖 1280x720 和常用宽屏；不要求手机视口。
- Three.js 截图和 canvas 像素检查证明场景非空、朝向和框选正确。
- UE 写入必须遵守 dry-run -> 用户确认 -> Apply -> 回读。
- 性能基线至少覆盖 100 个模块实例、每模块 500 个积木和 200 条连接；交互指标在技术验证阶段量化。

## 6. 旧系统处理

- 现有 `vendor/`、原 HTML 和 `USER_MANUAL.md`保持不变，标为 Legacy Reference。
- 当前 `src/integrations/`继续只修阻塞性问题，不再承载重做功能。
- `data/levels/`仍是用户数据，不由迁移测试覆盖或删除。
- 旧示例先作为迁移输入，不直接复制其临时 ID 或宿主 UI 状态。

## 7. 本次不启动的工作

- 连接器自动几何求解。
- 通用 CAD/平面图功能补齐。
- 手机端适配。
- 多格式 3D 导出。
- 大规模视觉重设计和品牌包装。

这些事项只有在 P0 UE 白盒闭环稳定且出现真实使用阻塞后，才重新评估。
