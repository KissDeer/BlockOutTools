## 1. 重做策略

采用旁路重做，不在现有 vendor 宿主上继续叠加功能。旧应用在迁移完成前保持可运行和只读参考；新应用拥有独立入口、领域模型和测试。

不从旧 DOM 或压缩 Store 复制内部结构。只复用经过确认的资产：UE 参数化 Schema、图标、示例关卡的设计意图、现有测试数据和已验证的坐标结论。

## 2. 建议技术边界

- TypeScript + Vite 作为应用基础。
- React 负责工作台界面；状态使用显式命令和事务 Store。
- 无限关系画布使用成熟节点图组件，不自研缩放、选区和连线基础设施。
- 节点几何编辑使用成熟 Canvas/SVG 场景库，领域模型与渲染节点分离。
- Three.js 只负责预览，几何由领域层提供。
- Zod 或等价 Schema 库负责文件与 HTTP 边界校验。
- Node 本地服务负责文件系统与 agent 桥接；浏览器不直接持有工程写权限。
- Vitest 覆盖领域逻辑；浏览器验收用真实桌面流程。

具体库在实现前用一个小型技术验证确定，不能让库的节点模型变成项目数据模型。

### 目录与依赖边界（建议；当前实现与建议有出入，以实际为准）

**领域层不依赖 UI。** 这是唯一不能破的边界，其余可以按实际调整。

```text
app-v2/
  src/domain/     # 纯数据、命令、历史、验证、展平几何（不得依赖 React / Canvas / Three.js / DOM / UE）
  src/features/   # 画布与面板，只消费 domain
  src/store/      # 事务 store
  server/         # 本地服务与 agent 桥接
scripts/          # UE 导出、生成夹具、诊断
```

**3D 预览与 UE 导出必须消费同一份展平几何。** 这两条现在各自从 `resolveAssembly` 出发（见 FR-06 / FR-07），改吃节点几何时要把这一步共用。

## 5. 质量门槛

- 所有 P0 需求有验收证据；**"代码里有"不算证据，界面上走得到才算。**
- 领域层关键逻辑至少覆盖：稳定 ID、命令事务、撤销重做、**节点展平**、Schema、规范、UE 计划。
- 浏览器覆盖 1280x720 和常用宽屏；不要求手机视口。
- Three.js 截图和 canvas 像素检查证明场景非空、朝向正确。
- 每步之后 `npx tsc -b` 与 `npx vitest run` 必须全绿。任何一步之后测试变红，就是这一步切错了。

## 6. 旧系统处理

- `data/levels/` 仍是用户数据，不由迁移测试覆盖或删除。
- 旧示例作为迁移输入，不复制其临时 ID 或宿主 UI 状态。
- 旧格式（`structureGraph`、`ueBlockout` 参数树）只在导入迁移时读取，不成为运行时模型。
